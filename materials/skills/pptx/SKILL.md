# 스킬: PowerPoint 파일로 바꾸기

학생이 만든 HTML 발표자료를 **.pptx 로 제출해야 할 때** 이 스킬을 따른다.

> 이 파일은 3주차 수업에서 학생과 함께 연다. **"맨손으로 하면 왜 안 되는지"가
> 여기 적혀 있다** — 도구를 쓰는 이유가 규칙에 적혀 있다는 것을 보여주는 자리다.

---

## 먼저 알아야 할 것 — 왜 직접 만들면 안 되나

pptx 는 확장자만 바꾼다고 되는 파일이 아니다. **zip 안에 XML 여러 장이 규격대로**
들어 있어야 한다. 규격을 모르고 직접 XML 을 쓰면 이렇게 된다 (2026-09-01 실측):

| 증상 | 원인 |
|---|---|
| 글자가 하나도 안 보인다 | 배경을 안 칠했다. 원본이 어두운 배경이라 글자색이 흰색인데, pptx 배경은 기본 흰색 → **흰 바탕에 흰 글씨** |
| PowerPoint 가 "복구해야 합니다"를 띄운다 | 색 지도(clrMap)·테마 목록이 규격을 어겼다 |
| 열리긴 하는데 서식이 다 빠졌다 | 슬라이드 마스터·레이아웃이 비어 있다 |

그래서 **규격을 대신 지켜 주는 도구(python-pptx)** 를 쓴다. 아래 순서를 지킨다.

---

## 순서 — 반드시 이대로

### 1. 원본을 확인한다

```bash
ls *.html
```

바꿀 HTML 이 어느 것인지 학생에게 확인받는다. **원본은 절대 지우거나 덮어쓰지 않는다.**

### 2. 변환한다

```bash
python3 ~/.codex/skills/pptx/html2pptx.py <원본>.html <결과>.pptx
```

슬라이드 수가 출력된다. 원본 장수와 같은지 학생과 함께 센다.

### 3. 확인한다 — 만들었다고 끝이 아니다

```bash
python3 -c "from pptx import Presentation; p=Presentation('<결과>.pptx'); print(len(p.slides), '장')"
```

- **장수**가 원본과 같은가?
- 학생 PC 로 내려받아 **실제로 열어 본다.** 열리는지, 글자가 보이는지 눈으로 확인한다.

> 여기까지 해야 "됐다"고 말한다. 파일이 생긴 것과 제대로 만들어진 것은 다르다.

### 4. 제출본으로 다듬는다

학교 조건(장수·표지 형식)이 있으면 원본 HTML 을 고치고 **다시 변환한다.**
pptx 를 직접 손대지 않는다 — 원본이 정본이고 pptx 는 결과물이다.

---

## 결과물 규칙

| 항목 | 값 | 이유 |
|---|---|---|
| 화면 비율 | 16:9 (13.333 x 7.5 inch) | 요즘 빔프로젝터 기본 |
| 배경 | 흰색 (명시적으로 칠한다) | 인쇄해도 잉크가 덜 들고, 흰 글씨 사고를 막는다 |
| 제목 | AITF 파랑 (#0075FF), 굵게 | 화면당 강조색 하나 |
| 본문 | 근검정 (#141414) | 흰 배경에서 가장 잘 읽힌다 |
| 글꼴 | 맑은 고딕 | **학생 윈도우 PC 에 이미 있는 글꼴** — 없는 글꼴을 지정하면 글자가 깨진다 |
| 한 장당 항목 | 7개까지 | 넘으면 잘라내고 알려준다 |

색·글꼴을 바꿔야 하면 `html2pptx.py` 위쪽 상수만 고친다. 도형에 색을 직접 쓰지 않는다.

---

## 하지 않는 것

- 원본 HTML 을 지우거나 덮어쓰지 않는다
- 파일만 만들고 "완성했어요"라고 말하지 않는다 — 3번 확인을 거친다
- pptx 안의 XML 을 직접 쓰지 않는다 (규격 위반으로 안 열린다)
- 없는 글꼴을 지정하지 않는다
