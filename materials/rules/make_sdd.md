# 이미 만든 프로젝트를 스펙 구조로 바꾸기

> 이 문서는 선생님이 관리해요. 고쳐도 다음 배포 때 원래대로 돌아갑니다.

`rules/sdd.md` 를 먼저 읽고 오세요. 이 문서는 **스펙 없이 이미 만들어버린**
프로젝트에 스펙을 거꾸로 입히는 방법이에요. 왜 하냐면 —

- 다음 기능을 **맡기려면** 스펙이 있어야 해요 (스펙 없는 프로젝트는 계속 앉아서 시켜야 함)
- 남(팀원, 미래의 나, 발표 볼 사람)이 **읽을 수 있는** 프로젝트가 돼요

## 순서 — AI에게 이렇게 시키면 됩니다

**1. 지금 상태를 스펙으로 역추출**

```
이 폴더의 코드를 읽고 spec.md 를 만들어줘.
- 목표: 이 프로젝트가 뭘 하는 물건인지 한두 문장
- 완성 기준: 지금 실제로 되는 것들을 체크된 목록으로
- 설계: 파일 구조와 데이터 흐름
- 하지 않는 것: 코드에 없는 것 중 헷갈릴 만한 것
```

**2. 스펙 검증 — 여기가 제일 중요해요**

AI가 쓴 spec.md 를 **직접 읽으면서** 확인해요:
- 실제로 안 되는데 체크돼 있는 항목이 있나? → 체크를 풀어요
- 되는데 빠진 항목이 있나? → 추가해요

AI는 코드에 있는 것을 "된다"고 믿는 경향이 있어요. **실제로 열어서 눌러본
사람은 나뿐**입니다.

**3. 남은 일을 미완성 기준으로 추가**

하고 싶었는데 못 한 것들을 빈 체크박스로 적어요. 이제 이 프로젝트는
"다음 작업을 맡길 수 있는" 상태가 됐어요.

**4. 커밋**

```bash
git add . && git commit -m "spec.md 추가 — 스펙 구조로 전환" && git push
```

## 끝나면 뭐가 달라지나요

전: "다음에 뭐 하려 했더라…" → 코드를 다시 뒤져야 함
후: spec.md 의 빈 체크박스가 곧 할 일 목록. 그대로 AI에게 맡기면 됨
