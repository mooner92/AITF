# SDD — 스펙을 먼저 쓰고 맡기기

> 이 문서는 선생님이 관리해요. 고쳐도 다음 배포 때 원래대로 돌아갑니다.

SDD(Spec-Driven Development)는 **"무엇이 되면 완성인가"를 먼저 글로 쓰고**,
만드는 일은 AI에게 맡기는 방식이에요. 지금까지는 터미널 앞에 앉아서 한 줄씩
시켰다면, 이제부터는 **스펙을 주고 자리를 비워도** 일이 굴러갑니다.

이 수업의 서버 자체가 이 방식으로 만들어졌어요 — 선생님 저장소의 `specs/` 폴더를
보면 똑같은 구조가 있습니다.

## 스펙 파일 만들기

프로젝트 폴더 안에 `spec.md` 하나를 만들어요:

```
final_project/
  spec.md        ← 이 문서
  (작업 파일들)
```

## spec.md 의 네 부분

```markdown
# 프로젝트 이름

## 목표
누가 쓰는 무엇인지 한두 문장으로.
(예: 우리 반 애들이 급식 메뉴를 미리 보는 웹페이지)

## 완성 기준
"무엇이 되면 끝인가"를 체크리스트로. 이게 스펙의 심장이에요.
- [ ] 오늘 급식이 첫 화면에 보인다
- [ ] 내일 메뉴로 넘길 수 있다
- [ ] 폰에서 열어도 안 깨진다

## 설계
어떻게 만들지 큰 그림만. 파일 구조, 쓸 도구, 데이터가 어디서 오는지.

## 하지 않는 것
이번엔 안 만드는 것도 적어요. AI가 곁길로 새는 걸 막아줍니다.
(예: 로그인 기능은 안 만든다)
```

## 왜 "완성 기준"이 심장인가요

AI에게 "급식 페이지 만들어줘"라고 하면 AI 마음대로 만들어요.
완성 기준을 주면 **AI 가 그 목록을 하나씩 지우면서** 일합니다.
검사도 쉬워요 — 돌아와서 체크리스트만 확인하면 되니까요.

## 맡기는 법

```
spec.md 를 읽고 완성 기준을 순서대로 구현해줘.
끝난 항목은 체크 표시로 바꿔줘.
```

그리고 자리를 비웁니다. 돌아와서 할 일은 셋 — **체크 확인 → 실제로 되는지
열어보기 → 부족하면 스펙을 고쳐서 다시 맡기기.**
