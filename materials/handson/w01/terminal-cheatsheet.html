터미널 명령어 정리

오늘 서버에 접속해서 실제로 친 명령어들이에요. 이대로 다시 해보면 그대로 복습이 됩니다.

오늘 쓴 명령어 여섯 개

ssh 내 컴퓨터에서 수업 서버로 접속합니다. 계정 카드의 아이디·비밀번호를 씁니다.
$ ssh 내아이디@서버주소Password: (쳐도 화면엔 안 보여요 — 그대로 치고 Enter)

처음 접속할 때만 "이 서버를 신뢰합니까?"라고 물어요 → yes 입력. 학원에서만 접속됩니다.

ls 지금 있는 폴더 안에 뭐가 있는지 봅니다(list). ls -a를 붙이면 숨겨진 파일까지 다 보여요.
$ lsproject$ ls -a. .. .bashrc .codex project (점으로 시작하는 게 숨김 파일)
cd 폴더 안으로 들어가거나(cd 폴더이름) 다시 나옵니다(cd ..).
$ cd project(project 안으로 들어감 — 프롬프트가 project로 바뀜)$ cd ..(한 단계 위로 나옴)

그냥 cd만 치면 어디에 있든 내 홈 폴더로 돌아와요.

cat 파일 내용을 화면에 그대로 출력합니다. 편집은 안 되고 보기만.
$ cat AGENTS.md(파일 내용이 주르륵 출력됨)
nano 파일을 열어서 고치는 편집기. 화면 아래에 단축키 안내가 항상 떠 있어요.
$ nano AGENTS.md(편집 화면으로 바뀜 — 저장 Ctrl+O → Enter, 나가기 Ctrl+X)
clear 화면이 지저분해지면 싹 지웁니다. 파일이 지워지는 게 아니라 화면만 정리돼요.
$ clear

오늘 실제로 나온 실수들 — 전부 정상적인 과정이에요

cd.. → 안 됨  ·  cd .. → 됨
cd와 .. 사이에 띄어쓰기가 꼭 필요해요. 터미널에서 명령어와 대상은 항상 한 칸 띄웁니다.
cd projsct · cd porject → "No such file or directory"
폴더 이름 오타예요. 꿀팁: cd pro까지만 치고 Tab 키를 누르면 나머지를 자동으로 완성해줘요. 오타가 원천 차단됩니다.
cat Agent.md → 안 됨  ·  cat AGENTS.md → 됨
터미널은 대문자·소문자를 다른 글자로 봅니다. 파일 이름은 ls로 확인한 그대로, 한 글자도 다르면 안 돼요. 여기도 Tab 완성이 통합니다.
SERVER-RULES.md (파일 이름만 침) → "command not found"
파일 이름만 치면 터미널이 그걸 명령어인 줄 알아요. 파일을 보고 싶으면 앞에 cat을 붙여서 cat SERVER-RULES.md 이렇게 씁니다.
is → "command not found"
ls의 오타예요. 소문자 L + s 입니다.
nano로 AGENTS.md 저장 시도 → "Permission denied"
이건 실수가 아니라 일부러 막아둔 거예요. AGENTS.md는 수업용 지시서라 읽기만 되고 고칠 수는 없게 돼 있어요. 여러분 잘못이 아닙니다.

딱 하나만 기억한다면

안 될 때 당황하지 말고 오류 메시지를 그대로 읽으세요. "command not found"는 명령어 오타, "No such file or directory"는 이름 오타. 오늘 나온 실수 전부, 메시지가 이미 답을 말해주고 있었어요. 그리고 Tab 키 — 이름을 반쯤 치고 Tab을 누르는 습관만 들여도 오타의 절반이 사라집니다.
