# 130 — 개강 전 작업 계획 (외부 의존 대기 구간)

**상태** `Active` · 기간: 지금 ~ 학원 IP·GPT 계정·학생 gmail 수령일

---

## 전제

받기 전까지 **할 수 없는 것**과 **할 수 있는 것**이 명확히 갈립니다.
이 구간에는 후자에만 집중하고, 전자는 받는 즉시 30분 안에 끝나도록 미리 준비해 둡니다.

### 지금 막혀 있는 것 (외부 의존)

| 막힌 것 | 필요한 것 | 풀리면 걸리는 시간 |
|---|---|---|
| 학생 계정·저장소·포트 일괄 생성 | 학생 명단 + gmail | 10분 (스크립트 완비) |
| AI CLI 실동작·비용 실측 | GPT API 키 | 반나절 (온보딩 6단계) |
| 학원에서 인증 없이 접속 | 학원 고정 IP | 10분 (Access Bypass 규칙) |
| Slack 워크스페이스 개설 | 학생 gmail | 반나절 |
| 모델 비교 봇 | GPT 키 + 회사 서버 승인 | 1~2일 |

**중요**: 위 다섯은 전부 **스크립트·문서가 이미 준비된 상태**입니다.
받는 날 헤매지 않도록, 이 구간의 목표는 "받으면 바로 실행"을 만드는 것입니다.

## 이 구간의 우선순위

### 1순위 — 수업이 성립하는지 확인 (내용)

키 없이도 되는 것부터. **1주차가 실제로 2시간에 들어가는지**가 최대 미확인 항목입니다.

- [ ] **1주차 슬라이드 완성** — 지금 20장, 해요체 미적용 상태. 문체 규정(design-spec 2.5) 적용
- [ ] **1주차 완성 예시 제작** — 프로필 카드 실물. 첫 시간에 "12주 뒤 여러분의 작품관"으로 띄울 것
- [ ] **2~3주차 슬라이드 초안** — 2주차(Codex 구조+모델), 3주차(발표자료)
- [ ] **시간 배분 검증** — 슬라이드 노트의 합이 120분에 맞는지 (1주차는 완료, 2·3주차 미실시)
- [ ] **접속 5단계 리허설** — 시험 계정으로 처음부터 끝까지. 25분 가정이 맞는지 실측

### 2순위 — 스킬 완성도 (수업 재료)

- [ ] **`$aitf-deck` 실동작 확인** — 키 수령 후 즉시. 지금은 배포·연결만 완료, 호출 미검증
- [ ] **스킬 3개 문서 다듬기** — 학생이 읽고 이해되는지 기준으로 재검토
- [ ] **해부용 well-made 하네스 분석** — 5주차 수업 대본. oh-my-codex 계열 clone → 트리거·지시
      구조·모델 전환 지점 정리 (키 불필요, 지금 가능)
- [ ] **6주차 봇 뼈대 구축** — 웹훅 수신·발신 골격. 학생은 스킬 로직만 꽂게
- [ ] **공공데이터포털 공용 키 신청** — 발급에 하루쯤 걸림. **지금 신청해 둘 것**
- [ ] **Flow 영상 1편 실측** — 크레딧 소모량 확인 (8주차 단체 세션 확정 근거, specs/140)
- [ ] **Gemini Notebook 예행** — 지금 저장소 문서를 올려 "우리 수업을 아는 AI"를 만들어 보기
      (11주차 실습의 강사 리허설 겸, 계획서 사각지대 점검용)

### 3순위 — 환경 세팅 (받는 날 대비)

- [ ] **자동 위키 생성 스크립트** — 선행 의존. 이게 없으면 Notion 발행·Slack 알림·7주차 공개가
      전부 못 굴러감. **1주차부터 데이터가 쌓여야 하므로 개강 전 필수**
- [ ] **위키 그래프 시각화 페이지** — 7주차 공개 장면의 실물
- [ ] **Playwright MCP 설치·검증** — 7주차. 6명 동시 부하 실측 포함
- [ ] **오프라인 안내 페이지 배치** — `/srv/fallback/offline.html` (파일은 있음, 배치 안 됨)
- [ ] **부트 볼륨 백업** — 운영자 콘솔 1회. 미뤄진 지 오래됨

### 4순위 — 받는 즉시 실행할 것 (미리 리허설만)


## 개강 이틀 전 — 학원 현장 리허설 (금요일)

**목적**: 학생이 실제로 겪을 접속 과정을 학원 노트북·학원 네트워크에서 그대로 재현하고,
문제가 있으면 로그를 보며 그 자리에서 고친다.

### 준비물

- 학원 노트북 (수업에 실제로 쓰일 것)
- 이 PC에 Claude Code 로그인 (서버 로그를 같이 보며 진단하기 위함)
- 학생 명단 확정 전이므로 **시험 계정 하나**로 진행

### 순서

1. **시험 계정 생성** — `bash1` 등, 학생과 **동일 권한**으로
   ```bash
   echo "bash1,$(openssl rand -base64 12)" > /tmp/test-account.csv
   ./scripts/create-accounts.sh /tmp/test-account.csv
   ./scripts/alloc-ports.sh /tmp/test-account.csv --deploy
   ./scripts/deploy-skills.sh
   ```
2. **브라우저 터미널 흐름 처음부터 끝까지** (이게 이 날의 핵심)
   - 학원 네트워크에서 접속 → 계정·비밀번호 → 터미널 진입까지 걸리는 시간 실측
     (`specs/130` 미검증 표의 "1주차 접속 25분" 가정을 여기서 검증한다)
   - tmux 3키, 첫 프롬프트, 스킬 호출(`$aitf-deck`)까지 학생 입장에서 그대로 수행
   - **막히는 지점마다 그 자리에서 서버 로그를 확인** — Claude Code로 로그를 열어
     원인을 같이 짚고, 가능하면 그 자리에서 고친다 (검증 원칙 문서의 "실행되는 것으로
     확인한다" 원칙 그대로)
3. **SSH 경로 시험** (160) — **학원 고정 IP가 확보되고 방화벽 승인이 난 경우에만.**
   확보 전이면 이 항목은 건너뛰고 브라우저 흐름 검증에 시간을 더 쓴다

### 이 리허설이 끝나면 알게 되는 것

- 1주차 접속 25분 가정의 실측치
- 학원 네트워크에서 막히는 것이 있는지 (academy-request.md 2-2가 왜 필요한지 실증)
- 시험 계정 권한이 설계대로 동작하는지 (sudo 없음, 홈 밖 접근 불가)
