# 055 — P4-1: 교육용 하네스 ★최대 작업

**상태**: In Progress · 제작·배포·스키마 검증 완료 (2026-08-18) · 동작 검증은 API 키 대기

> ⚠️ **스포일러 정책**: 하네스의 실제 내용(프롬프트·라우팅 규칙)은 수업 중 "리빌" 주차의 핵심 재료다.
> 리빌 전까지 **이 repo에 커밋하지 않는다**. 리빌 후 `harness/` 디렉토리로 공개한다.
> 이 스펙에는 구조와 요구사항만 기술한다.

## 목표

학생이 쓰는 AI 에이전트의 동작을 감싸는 하네스. 비용을 통제하고, 프로젝트 맥락을 주입하고, 무엇보다 **AI가 가르치게** 만든다.

## 요구사항 (3층)

1. **모델 라우팅** — 기본 모델 / 단순 작업·하위 에이전트는 경량 모델. 토큰 관측(070)으로 비율 검증 가능해야 함.
2. **프로젝트 맥락** — 이번 기수 스택, 자주 나는 에러와 해법, 파일 구조.
3. **교육 원칙** — **"고치기 전에 뭐가 왜 틀렸는지 쉬운 한국어로 먼저 설명할 것."**
   조용히 고쳐주면 학생은 아무것도 배우지 못한다. 하네스에서 가장 중요한 한 줄.

부가 요구사항: 주석을 충실히 단다 — 리빌 때 화면에 그대로 띄우는 교재가 된다.

## 배치 설계

`/opt/harness` — root:root 소유, 파일 644 / 디렉토리 755 (학생 읽기 가능·수정 불가):

| 파일 | 역할 | 배포 |
|---|---|---|
| `AGENTS.md` | 하네스 본문 (2·3층). CLI가 작업 디렉토리에서 읽는 컨텍스트 파일 | `~/project/AGENTS.md` **심링크** (수정 불가) |
| `codex-config.toml` | 1층 모델 라우팅 | `~/.codex/config.toml` **사본 600** (키가 들어갈 수 있고, 12주차에 학생이 직접 조정한다) |
| `README-instructor.md` | 리빌 진행 순서와 3층 대응표 (강사용) | 배포 안 함 |

- 배포 스크립트: `/opt/scripts/link-harness.sh <계정>`
- `/etc/gitignore`에 `AGENTS.md`·`.codex/`·`harness` 추가 → 저장소 유출 이중 차단

### 1층 라우팅이 동작하는 방식

기본 모델은 저가 티어. 어려운 문제를 만나면 **하위 에이전트**(`[agents.deep]`, 중간 티어)에게 넘긴다.
학생은 모델을 고르지 않는다 — 설정 파일이 대신 고른다. 이게 10주차 리빌의 도입부다.

CLI의 `--strict-config`로 스키마를 실측 검증했다 (`model`, `[agents.<name>] model/description/instructions`,
`model_reasoning_effort`, `sandbox_mode`, `approval_policy`, `[tools] web_search` 전부 인식됨).
**추측으로 쓴 설정이 아니라 파서가 통과시킨 설정이다.**

### 안전장치가 하네스에 포함된 이유

`sandbox_mode`(작업 폴더 밖 쓰기 차단)와 `approval_policy`(위험한 명령은 학생에게 확인)를
하네스에 넣어 두면, 리눅스 계정 격리 위에 **한 겹 더** 쌓인다.
동시에 "AI가 뭘 하려는지 보고 승인하는" 습관을 기르는 교육 장치이기도 하다.

### 스포 방지 장치

본문 마지막 절에서 "모델이 왜 둘?", "deep이 뭐?", "이거 RAG?" 류 질문에
AI가 정답 대신 "수업에서 공개할 거예요"로 답하도록 지시해 두었다.
