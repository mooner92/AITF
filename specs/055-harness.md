# 055 — P4-1: 교육용 하네스 ★최대 작업

**상태**: In Progress · 1차 제작·배포 완료 (2026-08-16), 모델 ID 확정과 동작 검증은 API 키 대기

> ⚠️ **스포일러 정책**: 하네스의 실제 내용(프롬프트·라우팅 규칙)은 수업 중 "리빌" 주차의 핵심 재료다.
> 리빌 전까지 **이 repo에 커밋하지 않는다**. 리빌 후 `harness/` 디렉토리로 공개한다.
> 이 스펙에는 구조와 요구사항만 기술한다.

## 목표

학생이 쓰는 AI 에이전트의 동작을 감싸는 하네스. 비용을 통제하고, 프로젝트 맥락을 주입하고, 무엇보다 **AI가 가르치게** 만든다.

## 요구사항 (3층)

1. **모델 라우팅** — 기본 모델 / 단순 작업·하위 에이전트는 경량 모델. 토큰 관측(070)으로 비율 검증 가능해야 함.
2. **프로젝트 맥락** — 이번 기수 스택, 자주 나는 에러와 해법, 파일 구조.
3. **교육 원칙** — **"고치기 전에 뭐가 왜 틀렸는지 쉬운 한국어로 먼저 설명할 것."**
   조용히 고쳐주면 학생은 아무것도 배우지 못한다. 하네스에서 가장 중요한 한 줄.

부가 요구사항: 주석을 충실히 단다 — 리빌 때 화면에 그대로 띄우는 교재가 된다.

## 배치 설계

- `/opt/harness` — root:root 소유, 755 (학생 읽기 가능·수정 불가)
- 각 학생 홈에 **심볼릭 링크** — 학생 저장소에 딸려 올라가지 않게 (060 전역 gitignore와 이중 방어)

## 구현 (2026-08-16)

`/opt/harness/` (root 소유, 파일 644 / 디렉토리 755):

| 파일 | 역할 |
|---|---|
| `AGENTS.md` · `GEMINI.md` | 하네스 본문 (2·3층). 두 CLI가 각각 읽는 컨텍스트 파일 규약이라 같은 내용을 두 이름으로 둔다 |
| `codex-config.toml` · `gemini-settings.json` | 1층 모델 라우팅. 학생 홈의 `.codex/`·`.gemini/`로 **사본** 배포(키가 들어갈 수 있어 심링크 아님) |
| `README-instructor.md` | 리빌 진행 순서와 3층 대응표 (강사용) |

- 학생 홈 배치: `~/project/AGENTS.md`·`GEMINI.md` → `/opt/harness/*` **심링크** (`/opt/scripts/link-harness.sh <계정>`)
- `/etc/gitignore`에 `AGENTS.md`·`GEMINI.md`·`harness` 추가 → 저장소 유출 이중 차단
- **스포 방지 장치**: 본문 마지막 절에서 "모델이 왜 둘?", "이거 RAG?" 류 질문에 AI가 정답 대신 "수업에서 공개할 거예요"로 답하도록 지시
