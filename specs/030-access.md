# 030 — P2: 접속 경로·보안 잠금

**상태**: In Progress · 터널 라우팅 구축 완료 (2026-08-16 기준 도메인 확정, 2026-08-17 적용) · 차단: **Access 정책**(운영자 대시보드 작업), 학원 고정 IP

## 목표

학생은 학원에서 **브라우저만으로** 로그인 화면 없이 서버 터미널에 접속한다.
집에서도 이어서 할 수 있게 하되, 그건 **선택**이다(숙제는 여전히 서버 없이 가능).
강사는 어디서든 OTP로 관리 경로 접속. 마지막에 공인 SSH 포트를 닫아 공격면 제거.

## ⚠️ 잠금 순서 (틀리면 운영자 본인이 잠긴다)

**새 경로 3중 검증 통과 전에는 절대 포트 22를 닫지 않는다.**

## 설계

- 기존 Cloudflare 터널(로컬 관리형, config.yml)에 ingress 3개 추가 — 새 터널 만들지 않음:
  ```yaml
  # /etc/cloudflared/config.yml (기존 항목 위, 404 폴백 앞에 추가)
  - hostname: ssh.<domain>
    service: ssh://localhost:22
  - hostname: git.<domain>
    service: http://localhost:3000
  - hostname: mon.<domain>
    service: http://localhost:8080
  ```
- DNS 라우팅: `cloudflared tunnel route dns <TUNNEL_ID> ssh.<domain>` (git/mon 동일)
- Zero Trust Access 애플리케이션 (정책 설계는 아래 "학생 접속" 절 참조)
- ssh 앱은 **브라우저 렌더링(SSH) ON**

## 구축 결과 (2026-08-17)

| 호스트명 | 서비스 | 상태 |
|---|---|---|
| `mon.<domain>` | OpenObserve 127.0.0.1:8080 | ✅ 연결·검증 완료 (HTTP 200, OpenObserve 응답 확인) |
| `git.<domain>` | Gitea 127.0.0.1:3000 | ✅ 연결·검증 완료 (HTTP 200, Gitea 응답 확인) |
| `sshopc.<domain>` | sshd 22 | ⛔ **의도적으로 비활성** — config.yml에 주석 처리. Access 정책 생성 후에만 해제 |
| 기존 서비스 | (변경 없음) | ✅ 회귀 확인 10/10 정상 |

### 구축 중 발견·처리한 문제 2건

1. **고아 replica가 라우팅을 오염시키고 있었다.** 같은 터널에 replica 2개가 붙어 있었는데, 하나는 시스템 서비스(config.yml 기반), 다른 하나는 수개월 전 수동 실행된 고아 프로세스로 `--url` 플래그를 쓰고 있었다. `--url`은 **모든 호스트명을 한 서비스로 강제 라우팅**하므로, 새 호스트명을 추가해도 요청의 절반이 엉뚱한 서비스로 갔을 것이다. 고아 프로세스를 정리하고 커넥터 1개로 통일 (기존 서비스 회귀 확인 후 실행).
2. **`ssh.<domain>` DNS 레코드가 이미 존재했다.** (와일드카드 아님 — 없는 서브도메인은 응답 없음) ingress 규칙을 켜면 Access 정책 없이 SSH가 열릴 수 있어 즉시 규칙을 주석 처리했다. 확인 결과 이 호스트명은 **우리 터널이 아닌 다른 곳**을 가리키고 있었고, 운영자 확인 결과 **다른 서버가 쓰는 레코드**였다. → 수업용은 `sshopc.<domain>`(Oracle 서버임을 명시)로 분리한다. 기존 레코드는 건드리지 않는다.

## 학생 접속: 정책 2개 (2026-08-18 결정)

원래는 학원 IP Bypass **하나만** 두고 외부를 원천 차단할 계획이었다. 이를 변경한다:

| 정책 | 대상 | 목적 |
|---|---|---|
| ① `Bypass` | 학원 고정 IP | **수업 중 마찰 0** — 12명이 동시에 로그인 화면을 만나면 첫 10분이 날아간다 |
| ② `Allow` (One-Time PIN) | **희망 학생만** 이메일 등록 | 집에서도 이어서 할 수 있게 |

**변경 이유**: 관측이 이미 학생별 토큰·리소스·진도를 잡고 있고(평시 15분 주기, tokscale에 시간대별
리포트 있음), 비용 상한은 API hard cap이 독립적으로 막는다. 외부 접속을 원천 차단할 근거가 약해졌다.
반면 "집에 가서 다시 세팅하기 귀찮아서 안 한다"는 마찰은 실제로 학생을 막는다.

**학원 IP는 여전히 필요하다 — 이유가 바뀌었을 뿐이다.** 보안 경계가 아니라 **수업 중 로그인 생략**용이다.
IP가 유동이면 정책 ①을 못 쓰고 수업 중에도 OTP를 쳐야 하므로, 개강 전 반드시 확인한다.

**이메일 수집은 전원이 아니라 선택**으로 둔다. 중등반은 만 14세 미만이 포함될 수 있어 개인정보 동의
문제가 있다(커리큘럼이 GitHub를 피한 것과 같은 이유). 원하는 학생만 등록하면 이 문제가 크게 줄어든다.

⚠️ **집 접속을 허용하되, 숙제를 그것에 의존시키지 않는다.** 커리큘럼의 숙제 원칙("서버 접속 불필요,
5~10분, 종이/폰으로 가능")은 그대로 유지한다. **허용과 전제는 다르다** — 전제로 삼는 순간
"컴퓨터 학원은 학생에게 2~3순위"라는 원칙이 무너진다.

### 파급 효과 2가지

- **비용 추정 재조정**: [050](050-ai-layer.md)의 12주 ~$97은 수업 시간만 가정한 값이다. 집 사용이
  붙으면 2~3배까지 갈 수 있다. hard cap이 상한을 막지만, cap 값을 그만큼 잡아야 한다.
- **부하 테스트 전제**: 동시 6명 가정이 느슨해진다. 다만 집에서 12명이 동시에 붙는 경우는 드물어
  기존 여유(메모리 13GB)로 충분하다.

## 검증 기준

- [ ] 외부에서 `nmap -p22 <SERVER_IP>` → filtered/closed
- [ ] 학생 시나리오 A(수업): 학원 IP → 브라우저 → 로그인 화면 없이 터미널
- [ ] 학생 시나리오 B(집): 등록 이메일 OTP → 같은 계정·같은 작업 상태로 접속
- [ ] 기존 터널 서비스 무영향

## 락아웃 복구 경로 (사고 대응)

Cloudflare 관리자 ssh 경로 → 안 되면 자택 IP 직통 22 → 최후에 OCI Cloud Shell 시리얼 콘솔.
