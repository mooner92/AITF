## 1. Slack — 학원 명의 계정으로

### 충돌과 해법

Slack은 이메일 없이는 가입이 안 된다. 그런데 우리는 학생 이메일을 받지 않기로 했다(110).

**해법: 서버 계정과 똑같이 학원(강사) 명의로 만든다.**
강사 소유 도메인에 별칭 메일 12개(`mid01@…`)를 만들고, 그걸로 Slack 계정을 미리 생성해
계정 카드와 함께 나눠준다. 학생은 아무것도 가입하지 않는다 — 서버 계정과 같은 원리라
**"만들 계정 없음" 약속이 유지된다** (학생이 만드는 게 아니라 학원이 발급).

### 채널 구성

| 채널 | 용도 |
|---|---|
| `#공지` | 강사만 씀. 자료 링크(Notion) 고정 |
| `#질문` | 질문은 여기로 — 스레드로 답해 같은 질문 반복 방지 |
| `#작품` | 매주 작품관 링크 공유. 서로 구경 |
| `#모델비교` | 비교 봇 전용 (아래 3절) |
| `#위키` | 일요일 20시 자동 위키 요약이 올라옴 |

### 알아둘 것

- **무료 플랜은 메시지 90일 보관** — 12주 과정에는 충분하나, 수료 시점에 내보내기를 한다
- **학부모는 Slack을 쓰지 않는다.** 학부모 소통은 학원 공지 채널(기존 방식)로 유지 —
  두 집단을 한 도구에 넣으면 어느 쪽도 편하지 않다
- 수료 후 워크스페이스는 보관 처리, 별칭 메일은 삭제

## 2. Notion — 주간 수업 정리 자동 발행

### 흐름

```
일 18:00 수업 종료
  → 20:00 서버 크론: 활동 수집 → 위키 md 생성 (v8 계획 3절, 기존 설계)
  → 20:30 요약 md → Notion 페이지 생성 (주차별 하위 페이지)
  → Slack #위키 채널에 링크 알림
```

**정본은 서버 위키(Gitea)다.** Notion은 읽기 좋은 발행본이며, 학생·학부모가 링크 하나로
복습하는 용도다. Notion이 죽어도 수업 데이터는 서버에 있다.

### Notion 연동 설정 (두 가지 — 용도가 다르다)

**ⓐ 자동 발행(크론)은 MCP가 아니라 API 직결로 한다.**
MCP는 대화형 에이전트가 도구를 쓰는 프로토콜이라, 정해진 문서를 정해진 시간에 올리는
일에는 LLM도 MCP도 필요 없다. 스크립트가 REST API를 부르는 쪽이 실패 지점이 적다.

```
1. notion.so/profile/integrations → 새 내부 통합(Internal) 생성 → 토큰 발급
2. 발행 대상 페이지 우상단 ⋯ → 연결(Connections) → 방금 만든 통합 추가
3. 서버 크론 스크립트가 토큰으로 pages.create 호출 (토큰은 /opt/scripts/.env, 600)
```

**ⓑ 강사가 대화로 정리·수정할 때는 MCP를 쓴다.**

```bash
# Claude Code
claude mcp add notion --env NOTION_TOKEN=<토큰> -- npx -y @notionhq/notion-mcp-server
# Codex CLI — ~/.codex/config.toml
[mcp_servers.notion]
command = "npx"
args = ["-y", "@notionhq/notion-mcp-server"]
env = { NOTION_TOKEN = "<토큰>" }
```

이후 "이번 주 정리 페이지에서 3절만 더 풀어서 써줘" 같은 작업을 대화로 한다.

## 3. 모델 비교 봇 — 이 스택의 백미

학생들은 GPT·Gemini 챗만 써봤다. **같은 질문에 모델마다 다르게 답하는 것을 나란히 보는 것**이
"모델을 고른다"(3주차)를 몸으로 만든다.

### 구조

```
학생: /compare 김치찌개 레시피를 세 줄로
  → Slack 봇 (학원 서버에서 구동)
  ├─▶ 회사 서버 로컬 모델 (qwen · gemma)   ← Zero Trust 서비스 토큰
  └─▶ 학원 GPT 키 (luna)                   ← 기존 상한 안에서
  → 스레드에 모델별 답 + 응답 시간 + 예상 비용 나란히
```

- **학생은 회사 서버에 직접 닿지 않는다.** 봇 프로세스만 서비스 토큰을 갖고,
  토큰은 학원 서버의 봇 환경에만 있다 (Zero Trust Access 서비스 토큰 방식)
- 로컬 모델 호출은 **무료**라 부담 없이 쓰게 두고, GPT 경유는 봇이 횟수 제한
- 응답에 시간·비용을 같이 찍는다 — "빠르고 공짜인데 조금 어색함 vs 느리고 유료인데 매끄러움"이
  숫자로 보인다

### ⚠ 확인 필요

**회사 서버 자원을 수업에 쓰는 것은 회사 승인 사항이다.** 기술적으로 되는 것과 해도 되는 것은
다르다 — 사용량 상한·시간대·로그 정책을 회사와 합의한 뒤 붙인다. 승인 전까지 봇은
로컬 모델 없이 GPT 단독으로도 동작하게 만든다 (강등 경로).

## 4. Claude 디자인 체험 — 구독 연결은 하지 않는다

**개인 Claude 구독을 학생용 Slack에 연결하는 것은 권장하지 않는다.**
구독 약관상 계정 공유·제3자 사용에 해당할 소지가 있고, 학생 6명이 쓰면 강사 본인의
사용량 한도를 수업이 잠식한다.

**대안 (수업 시간 단체 세션)**: 프로젝터로 강사 계정을 띄우고 **반 전체가 지시문을 함께
만들어** 디자인을 뽑는다. 학생들이 문장을 제안 → 강사가 입력 → 결과를 같이 평가 → 수정.
"지시문이 디자인을 바꾼다"를 전원이 동시에 목격하는 구성이라 오히려 교육 효과가 크다.
같은 주제를 각자 Codex로 재현하는 것까지가 한 세트다 (디자인 스펙 스킬 활용).

GPT 쪽 대응물: Codex CLI 자체가 HTML/CSS 생성이 되므로 별도 도구가 필요 없다.

## 5. n8n — 셀프호스트라 무료다

**비용 걱정은 사실과 다르다.** 유료는 n8n Cloud이고, **셀프호스트는 무료**다(fair-code).
학원 서버 docker로 띄우면 라이선스 비용이 없다.

### 키 전략 — 학생 개인 키는 안 된다

학생 각자 Gemini 키를 받게 하면 두 가지가 깨진다.

1. **"만들 계정 없음" 약속** — Google 계정 + AI Studio 가입이 필요하다
2. **만 14세 미만**은 한국에서 보호자 동의 없이 Google 계정을 만들 수 없다 (중등반 문제)

**→ 학원 명의 Gemini 키 1개**(무료 티어)를 봇과 같은 방식으로 서버에만 둔다.
무료 티어 분당 한도 안에서 6명이 데모용으로 쓰기에는 충분하고, 초과하면 대기시키면 된다.
GPT 키는 말씀대로 소량만 — n8n 노드에서 호출 횟수를 워크플로 레벨에서 제한한다.

### 체험 워크플로 (7주차 재료 후보)

"트리거 → AI → 결과가 눈에 보이는 곳"의 3단 구성이 좋다.

> **예: 아침 브리핑 봇** — 매일 9시 트리거 → 날씨 API(무료) → Gemini가 오늘의 한 줄 브리핑 +
> 나노바나나(Gemini 이미지)로 날씨 그림 생성 → Slack #공지에 전송

수업 후에도 매일 아침 결과가 도착하므로 "내가 만든 게 계속 돌아간다"는 감각이 남는다.
영상 생성(Higgsfield 등)은 **유료라 제외** — 영상은 8주차 ffmpeg 파이프라인으로 충분하다.

## 6. "친구들에게 보여줄 만한" 재료 풀

스킬 위크(5주)·프로젝트(9~12주) 재료 후보다. 전부 무료·브라우저 실행·자립 파일이라
작품관에 그대로 전시된다. **커리큘럼의 "재료는 교체 가능" 원칙에 따라 풀로 관리**하고
그때 반응 좋은 것을 쓴다.

| 재료 | 무엇이 나오나 | 왜 통하나 |
|---|---|---|
| **three.js 3D 명함** | 마우스로 돌리는 3D 이름·오브젝트 | 첫 반응이 가장 큰 "우와" 계열 |
| **p5.js 제너러티브 아트** | 내 이름을 시드로 한 나만의 무늬 | 전원이 다른 결과 — 비교하는 재미 |
| **Tone.js 비트메이킹** | 브라우저에서 도는 나만의 비트 | 소리는 공유성이 가장 강함. 8주차 영상 BGM으로 연결 |
| **위키 그래프 시각화** | 우리 반 학습 지도 (이미 계획됨) | 자기가 노드로 들어 있음 |
| **QR 스티커** | 작품관 링크 QR 인쇄 | 폰으로 찍는 순간 오프라인 공유가 됨 |

## 도입 시점 매핑 — 새 주차는 없다

| 것 | 언제 | 어떻게 |
|---|---|---|
| Slack | 1주차부터 | 소통 인프라. 계정 카드에 Slack 정보 포함 |
| Notion 발행 | 1주차부터 | 자동 위키 파이프라인의 출력 하나 |
| 모델 비교 봇 | **3주차 정식 데뷔**, 이후 상시 | "모델을 고른다" 주차의 핵심 실습 도구 |
| 단체 디자인 세션 | 5주차 도입부 | 스킬 위크의 시연 |
| n8n | **7주차 재료 후보** | 에이전틱 주차 — Playwright와 택1 또는 시연 |
| 재미 재료 풀 | 5주·9~12주 | 반응 보고 선택 |

**v8 커리큘럼 구조는 그대로다.** 전부 기존 주차의 재료·인프라로 들어가며, 주차를 늘리거나
목표를 바꾸지 않는다.

## 준비 비용 (정직하게)

| 항목 | 준비량 | 우선순위 |
