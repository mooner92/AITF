# 010 — P0: 인스턴스 보전·디스크 확장

**상태**: In Progress · 2026-08-16

## 목표

이후 모든 작업의 안전 기반 확보: ① 전체 복구 지점(부트 볼륨 백업) ② 인스턴스 유지 리스크 해소 ③ 학생 홈·Gitea·스냅샷을 담을 디스크 공간.

## 현재 상태 (실사)

- VM.Standard.A1.Flex **4 OCPU / 24GB** — Always Free 최대치. 셰이프 변경 불필요.
- 루트 파일시스템 29.5G 중 **96% 사용(잔여 1.4G)** — 이대로는 P3 이후 진행 불가.
- 단, 부트 볼륨은 200G인데 파티션이 44.5G만 사용 → **~155G 미할당**. 콘솔 작업 없이 서버 내 확장 가능.
- 즉효 정리 대상: npm 캐시 ~8.3G, docker 빌드 캐시 ~0.8G.

## 작업 체크리스트

- [ ] **부트 볼륨 백업** (운영자, OCI 콘솔 → Boot Volume → Create Backup) — **이 스펙의 게이트. 백업 전 서버 변경 금지**
- [ ] 클라우드 공지(마감 8/18)의 정체 확인 (운영자) — 트라이얼 만료라면 A1 4/24는 Always Free 범위로 유지 가능(PAYG 전환 시 회수 위험 소멸), 유휴 회수 경고라면 상시 서비스 가동 중이라 해당 없음 가능성 큼
- [ ] ❌ 인스턴스 삭제 후 재생성 금지 — ap-seoul-1 A1은 "Out of capacity" 빈발, 재확보 실패 위험
- [ ] 디스크 확장 (백업 후):
  ```bash
  sudo /usr/libexec/oci-growfs -y
  # 실패 시 수동: growpart /dev/sda 3 → pvresize /dev/sda3
  #   → lvextend -l +100%FREE /dev/ocivolume/root → xfs_growfs /
  ```
- [ ] 캐시 정리: `npm cache clean --force` / `sudo docker builder prune -f`

## 결정 기록

- 2026-08-16 · "2 OCPU/12GB로 축소" 원계획 폐기 (000 참조). 24GB는 학생 동시 접속 + 기존 서비스 공존에 그대로 필요.
