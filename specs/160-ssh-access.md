**상태** `Draft` — **방화벽 변경(포트 22 개방)은 별도 승인 전까지 미적용**

## 0. 먼저 확정한 것 — 계정

**SSH는 `opc`(관리자) 계정으로 열지 않는다.** `opc`는 강사 개인 관리자 계정이고,
이 계정으로 학생이 접속하면 040에서 세운 계정 격리·sudo 차단이 전부 무의미해진다.

SSH는 **브라우저 터미널이 쓰는 것과 같은 학생 계정**(`mid01`, `high01` …)에
**두 번째 출입문을 여는 것**이다. 계정도 권한도 그대로다.

```
                ┌─ 브라우저 터미널 (기존, 기본)
학생 계정 mid01 ─┤
   (sudo 없음,   └─ SSH 직접 접속 (신규, 이 문서)
    홈 700)
```

같은 방에 문이 두 개 생기는 것이지, 더 큰 방으로 옮기는 게 아니다.

## 1. 왜 필요한가

- 강사가 **학생 입장에서 실제 접근을 재현**하고 서버 로그와 대조해 문제를 진단하기 위해
  (Claude Code를 학원 노트북에 직접 띄우고 로그를 보며 즉시 고치는 용도)
- 브라우저 터미널이 막혔을 때의 대체 경로
- (검토 중) 희망하는 고등부 학생에게 "진짜 개발자가 쓰는 접속 방식"을 보여주는 심화 자료

**기본 수업 경로는 바뀌지 않는다.** 브라우저 터미널이 여전히 기본이고,
SSH는 강사 도구 + 선택적 심화로 시작한다.

---

## 2. 접속 범위 — 학원 안에서만 (당장은)

| 범위 | 상태 |
|---|---|
| 학원 고정 IP에서만 | **이번 설계 대상** |
| 집·외부에서 SSH | **다루지 않음** — 외부 접속은 110의 브라우저 경로(서브도메인 + 인증)로 이미 설계돼 있다 |

**이유**: SSH를 인터넷에 통째로 열면 전 세계 스캐너의 표적이 된다.
**학원 고정 IP로 제한**하면 030·110에서 이미 쓰는 Bypass 패턴과 같은 방식이라
새 위험을 만들지 않는다. → **학원 고정 IP 확보가 이 설계의 전제 조건**이다
(academy-request.md 2-1, 이미 요청 중).

집에서도 SSH를 쓰고 싶어지면 그건 **별도 결정**이다 (Cloudflare Access의 SSH 프록시는
학생 PC에 `cloudflared` 설치가 필요해 "설치 없음" 약속과 충돌하므로, 필요해지면 그때 논의한다).

---

## 3. 접속 경로 — 기존 예약 이름 재사용

030 작업 중 **`sshopc.<도메인>`을 이미 확보**해 뒀다(다른 서버의 기존 `ssh.<도메인>`과
분리하기 위해). 이번에 그 이름을 실제로 쓴다.

```
학원 노트북 ──(고정 IP에서만 통과)──▶ sshopc.<도메인>:22 ──▶ 서버 sshd ──▶ mid01
```

- Cloudflare 프록시(주황 구름)를 거치지 않고 **DNS만**(회색 구름) 서버 IP를 가리키게 한다 —
  raw TCP는 Cloudflare 터널 경유가 아니라 직결이 더 단순하고, 인바운드는 방화벽으로 막는다
- 방화벽 규칙: `22/tcp` **학원 고정 IP에서만 허용**, 그 외 전부 차단

**⚠ 이건 방화벽 변경이다.** "포트 변경은 먼저 확인받는다"는 원칙에 따라
**아래 체크리스트의 방화벽 항목은 운영자 별도 승인 후에만 실행한다.**

---

## 4. 인증 — 계정별 키 한 쌍

- 계정마다 SSH 키 쌍 생성. **공개키만** `~/.ssh/authorized_keys`에 root가 등록(600, 학생이 못 고침)
- **개인키는 학생에게 전달**하고 서버에는 남기지 않는다
- 비밀번호 로그인은 막는다(`PasswordAuthentication no`) — 키만 허용
- 호스트 키 지문을 Notion 문서에 적어둬 **최초 접속 시 검증**하게 한다
  (이 자체가 "왜 known_hosts를 확인하는가"라는 좋은 보안 교육 소재다)

## 5. Notion 운영 문서 체계

### 5-1. 구조

```
AITF 워크스페이스 (학생만 초대 — 학부모·외부 비공개)
├── 📌 공지                         ← 고정. Slack #공지와 같은 링크
├── 📅 주차별 수업 페이지 (12개)      ← 120의 자동 발행이 채움
│    └── 1주차 · 2주차 · …
├── 🔑 SSH 설정                     ← 이 문서가 다루는 페이지
└── 🗺 우리 반 위키 그래프           ← 7주차 공개 후 연결
```

### 5-2. 주차별 수업 페이지 — 템플릿

120에서 설계한 자동 발행 파이프라인(일 20시 → 위키 → Notion)이 이 구조로 채운다.
자동 발행이 없는 주(파이프라인 완성 전)에는 강사가 이 뼈대로 수동 작성한다.

```markdown
# N주차 — {그 주 제목}

## 오늘 배운 것
- {개발 역량 1줄}
- {만들기 목표 1줄}

## 오늘 만든 것
🔗 내 작품관: (학생이 각자 붙여넣기)

## 오늘 쓴 도구
- {그 주 신규 도구}

## 사진
{강사가 수업 중 캡처 추가}

## 다음 주 예고
{다음 주 만들기 목표 한 줄}
```

- **정본은 서버 위키(Gitea)다.** Notion은 읽기 좋은 발행본 — 120의 원칙 그대로 유지
- 학생 실명 대신 **계정 ID**만 노출 (기존 위키 개인정보 규칙과 동일)

### 5-3. "SSH 설정" 페이지 — 템플릿 (실제 비밀 없이)

**이 저장소에는 자리표시자만 둔다. 실제 키·지문·IP는 Notion에만 존재한다.**

```markdown
# 🔑 SSH 설정

Codex 실습은 브라우저에서 그대로 합니다. 이 페이지는 **선택 사항**입니다 —
진짜 개발자가 쓰는 방식으로 접속해 보고 싶은 사람만 봐도 됩니다.

## 접속 정보

| 항목 | 값 |
|---|---|
| 주소 | ⟪HOSTNAME⟫ |
| 내 계정 | ⟪ACCOUNT⟫ |
| 포트 | 22 |

## 처음 한 번만 — 열쇠 받기

1. 아래 첨부된 개인 열쇠 파일(⟪ACCOUNT⟫.pem)을 내려받는다
2. **이 파일은 나만 갖는다.** 남에게 보내지 않는다 — 열쇠를 주는 것은
   내 계정 비밀번호를 통째로 주는 것과 같다

## 접속하는 법 (학원 노트북에서만 됩니다)

\`\`\`bash
ssh -i ⟪ACCOUNT⟫.pem ⟪ACCOUNT⟫@⟪HOSTNAME⟫
\`\`\`

## 처음 접속할 때 뜨는 경고

"이 서버를 신뢰합니까?"라는 문구와 함께 지문이 뜹니다. 아래 값과 **정확히 같은지** 확인하고
`yes`를 입력합니다. 다르면 접속하지 말고 강사에게 알립니다.

지문: ⟪HOST_KEY_FINGERPRINT⟫

> 왜 확인해야 할까요? 이 확인이 없으면 중간에서 누가 내 통신을 가로챌 수 있습니다.
> (7주차에 배우는 "AI에게 도구를 쥐여줄 때 승인을 받는 이유"와 같은 원리입니다.)
```

**⟪…⟫는 실제 배포 시 값을 채우되, 이 저장소(git)에는 절대 실값을 넣지 않는다** —
`.githooks/pre-commit`이 이런 패턴을 잡도록 이미 구성돼 있다(SECURITY.md).

## 7. 검증 기준

1. 학원 고정 IP 밖에서 22번 포트 접속 시도 → 거부됨
2. 시험 계정으로 SSH 접속 → 브라우저 터미널과 **동일한 권한**(sudo 없음, 홈 밖 접근 불가)
3. 비밀번호로 접속 시도 → 거부됨 (키만 허용)
4. 다른 학생 계정의 홈 디렉토리에 접근 시도 → 거부됨
5. Notion "SSH 설정" 페이지에 실제 비밀이 하나도 이 저장소에서 유래하지 않았는지 확인
