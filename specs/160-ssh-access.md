## 0. 먼저 확정한 것 — 계정

**SSH는 `opc`(관리자) 계정으로 열지 않는다.** `opc`는 강사 개인 관리자 계정이고,
이 계정으로 학생이 접속하면 040에서 세운 계정 격리·sudo 차단이 전부 무의미해진다.

SSH는 **브라우저 터미널이 쓰는 것과 같은 학생 계정**(`mid01`, `high01` …)에
**두 번째 출입문을 여는 것**이다. 계정도 권한도 그대로다.

```
                ┌─ 브라우저 터미널 (기존, 기본)
학생 계정 mid01 ─┤
   (sudo 없음,   └─ SSH 직접 접속 (신규, 이 문서)
    홈 700)
```

같은 방에 문이 두 개 생기는 것이지, 더 큰 방으로 옮기는 게 아니다.

## 1. 왜 필요한가

- 강사가 **학생 입장에서 실제 접근을 재현**하고 서버 로그와 대조해 문제를 진단하기 위해
  (Claude Code를 학원 노트북에 직접 띄우고 로그를 보며 즉시 고치는 용도)
- 브라우저 터미널이 막혔을 때의 대체 경로
- (검토 중) 희망하는 고등부 학생에게 "진짜 개발자가 쓰는 접속 방식"을 보여주는 심화 자료

**기본 수업 경로는 바뀌지 않는다.** 브라우저 터미널이 여전히 기본이고,
SSH는 강사 도구 + 선택적 심화로 시작한다.

## 2. 접속 범위 — 학원 안에서만 (당장은)

| 범위 | 상태 |
|---|---|
| 학원 고정 IP에서만 | **이번 설계 대상** |
| 집·외부에서 SSH | **다루지 않음** — 외부 접속은 110의 브라우저 경로(서브도메인 + 인증)로 이미 설계돼 있다 |

**이유**: SSH를 인터넷에 통째로 열면 전 세계 스캐너의 표적이 된다.
**학원 고정 IP로 제한**하면 030·110에서 이미 쓰는 Bypass 패턴과 같은 방식이라
새 위험을 만들지 않는다. → **학원 고정 IP 확보가 이 설계의 전제 조건**이다
(academy-request.md 2-1, 이미 요청 중).

집에서도 SSH를 쓰고 싶어지면 그건 **별도 결정**이다 (Cloudflare Access의 SSH 프록시는
학생 PC에 `cloudflared` 설치가 필요해 "설치 없음" 약속과 충돌하므로, 필요해지면 그때 논의한다).

## 3. 접속 경로 — 기존 예약 이름 재사용

030 작업 중 **`sshopc.<도메인>`을 이미 확보**해 뒀다(다른 서버의 기존 `ssh.<도메인>`과
분리하기 위해). 이번에 그 이름을 실제로 쓴다.

```
학원 노트북 ──(고정 IP에서만 통과)──▶ sshopc.<도메인>:22 ──▶ 서버 sshd ──▶ mid01
```

- Cloudflare 프록시(주황 구름)를 거치지 않고 **DNS만**(회색 구름) 서버 IP를 가리키게 한다 —
  raw TCP는 Cloudflare 터널 경유가 아니라 직결이 더 단순하고, 인바운드는 방화벽으로 막는다
- 방화벽 규칙: `22/tcp` **학원 고정 IP에서만 허용**, 그 외 전부 차단

**⚠ 이건 방화벽 변경이다.** "포트 변경은 먼저 확인받는다"는 원칙에 따라
**아래 체크리스트의 방화벽 항목은 운영자 별도 승인 후에만 실행한다.**

## 4. 인증 — 학원 IP 한정 비밀번호 (2026-08-28 개정)

> **개정 전 설계**: 계정별 SSH 키 쌍을 만들어 개인키를 학생에게 전달하고,
> `PasswordAuthentication no` 로 비밀번호를 완전히 막는다.
>
> **왜 바꿨나**: 이 설계는 SSH 가 **강사 도구 + 선택적 심화**라는 전제 위에 있었다.
> 그런데 브라우저 터미널이 개통되지 않은 채 개강이 이틀 앞으로 오면서 SSH 가
> **학생 전원의 유일한 접속 경로**가 됐다. 중고등학생 전원에게 개인키 파일을
> 배포·보관시키는 것은 1주차 접속 5단계를 8단계로 만들고, 키를 잃어버린 학생은
> 그 주 수업을 통째로 못 듣는다. 위험 대비 비용이 맞지 않는다.

**현재 구성** — `/etc/ssh/sshd_config.d/60-aitf.conf`

```
Match Address ⟪학원_고정_IP⟫
    PasswordAuthentication yes
```

- 전역 설정은 `50-cloud-init.conf` 의 `PasswordAuthentication no` 를 **그대로 둔다**.
  즉 **학원 IP 밖에서는 여전히 공개키만** 통과한다
- 포트 22 는 인터넷에 열려 있고 실제로 하루 수백 건의 무차별 시도가 들어오지만,
  그 출발지에서는 비밀번호 인증 자체가 꺼져 있어 **노출이 늘지 않는다**
- 비밀번호는 **8자 소문자+숫자**(`scripts/make-cards.py` 참조).
  헷갈리는 글자(`l`/`1`/`i`, `0`/`o`)와 대문자·특수문자를 뺀다 —
  터미널은 입력을 별표조차 찍지 않아 오타가 나도 어디서 틀렸는지 알 수 없다
- 학원 IP 가 바뀌면 이 파일 한 줄만 고치고 `systemctl reload sshd`

**키 방식을 폐기한 것이 아니다.** 브라우저 터미널이 열리거나 집에서의 접속이
필요해지면 그때 키 방식을 다시 검토한다 — 그 경우 이 절의 개정 전 설계가 출발점이다.

```markdown
Codex 실습은 브라우저에서 그대로 합니다. 이 페이지는 **선택 사항**입니다 —
진짜 개발자가 쓰는 방식으로 접속해 보고 싶은 사람만 봐도 됩니다.

## 접속 정보

| 항목 | 값 |

| 주소 | ⟪HOSTNAME⟫ |
| 내 계정 | ⟪ACCOUNT⟫ |

## 처음 한 번만 — 열쇠 받기

1. 아래 첨부된 개인 열쇠 파일(⟪ACCOUNT⟫.pem)을 내려받는다

## 접속하는 법 (학원 노트북에서만 됩니다)

\`\`\`bash
ssh -i ⟪ACCOUNT⟫.pem ⟪ACCOUNT⟫@⟪HOSTNAME⟫
\`\`\`

"이 서버를 신뢰합니까?"라는 문구와 함께 지문이 뜹니다. 아래 값과 **정확히 같은지** 확인하고
`yes`를 입력합니다. 다르면 접속하지 말고 강사에게 알립니다.

지문: ⟪HOST_KEY_FINGERPRINT⟫

> 왜 확인해야 할까요? 이 확인이 없으면 중간에서 누가 내 통신을 가로챌 수 있습니다.
> (7주차에 배우는 "AI에게 도구를 쥐여줄 때 승인을 받는 이유"와 같은 원리입니다.)
```

**⟪…⟫는 실제 배포 시 값을 채우되, 이 저장소(git)에는 절대 실값을 넣지 않는다** —

## 7. 검증 기준

1. **[통과 2026-08-28]** 학원 IP 에서 비밀번호 접속 → 성공.
   `sshd -T -C addr=⟪학원IP⟫` 가 `passwordauthentication yes` 를 반환
2. **[통과 2026-08-28]** 학원 IP 밖에서는 비밀번호 인증이 꺼져 있음.
   `sshd -T -C addr=⟪임의의_외부IP⟫` 가 `passwordauthentication no` 를 반환
3. **[통과 2026-08-28]** 접속 즉시 tmux 자동 진입, 창을 닫았다 다시 접속해도 내용 유지
4. 학생 계정으로 SSH 접속 → sudo 없음, 다른 학생 홈 접근 불가
5. Notion "SSH 설정" 페이지에 실제 비밀이 하나도 이 저장소에서 유래하지 않았는지 확인

> 검증 1·2 는 설정 파일을 읽어 확인하지 않는다. `sshd -T -C` 로 **실제 연결 조건을
> 넣었을 때 sshd 가 내리는 결론**을 본다 — `Match` 블록은 파일을 눈으로 읽어서는
> 적용 여부를 확신할 수 없다 (docs/verification-practice.md).

## 8. 결정 기록

- 2026-08-23 · **SSH는 `opc`가 아니라 학생 계정으로 연다.** 강사가 명확히 확인.
  이 결정으로 040의 계정 격리가 SSH 경로에도 그대로 유지된다.
- 2026-08-23 · 접속 범위를 **학원 고정 IP로 한정**한다. 외부(집) 접속은 이번 설계에서
  다루지 않으며, 필요해지면 별도 결정 사항으로 다룬다.
- 2026-08-23 · 방화벽 변경(포트 22 개방)은 **운영자 별도 승인 전까지 미적용**으로 명시.
  기존 원칙("포트 변경은 먼저 확인받는다")을 그대로 따른다.
- 2026-08-23 · `sshopc.<도메인>`을 재사용 — 030 작업 중 이미 이름만 예약해 둔 것을
  이번에 실제로 쓴다.
- 2026-08-28 · **SSH 가 보조 경로에서 주 경로로 승격됐다.** 1절의 "기본 수업 경로는
  바뀌지 않는다 — 브라우저 터미널이 여전히 기본"은 더 이상 사실이 아니다. 현장에서
  브라우저 터미널이 미개통(Cloudflare Access 정책 대기)임이 확인됐고, 개강까지 이틀이라
  SSH 로 1주차를 치른다. 브라우저 터미널은 폐기가 아니라 **연기**다.
- 2026-08-28 · **인증을 키에서 학원 IP 한정 비밀번호로 바꿨다** (4절). 전 학생에게
  개인키를 배포·보관시키는 비용이 얻는 안전보다 크다고 판단. 학원 밖에서는 여전히
  공개키만 통과하므로 외부 노출은 늘지 않는다.
- 2026-08-28 · **방화벽은 건드리지 않기로 했다.** 22 를 학원 IP 로 좁히면 강사가 집에서
  잠긴다. 인증 계층에서 이미 같은 제한이 걸려 있어 실익이 작다. 집 IP 를 함께 등록할
  준비가 됐을 때 다시 본다.
- 2026-08-28 · `sshopc` DNS 를 지금 붙이지 않는다. IP 직접 접속으로 동작이 확인됐고,
  이름은 편의일 뿐이라 개강 전 남은 시간을 여기에 쓰지 않는다.
- 2026-08-28 · **`reset-test-account.sh` 가 `.bash_profile` 을 복구하지 않아 리셋한
  계정만 tmux 자동 진입이 죽던 버그를 현장에서 발견**했다. 리허설 대본의 1번 단계가
  계정을 망가뜨리고 있었다 — 리허설을 실제로 돌려보지 않았으면 개강일에 터졌을 문제다.
  `/etc/skel` 을 먼저 깔도록 고치고 `test02` 로 재현·확인했다.
