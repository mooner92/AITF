# 060 — P5: Gitea + 학생 git 흐름

**상태**: Draft · 차단: 040

## 목표

학생 1인 1저장소. 학생 입장에서 git은 `add → commit → push` 3줄이 전부이도록 사전 구성(신원·인증·remote 전부 미리 주입).

## 설계

- **Gitea arm64 네이티브 바이너리** + 전용 시스템 계정 + systemd 유닛 (Docker 아님 — SELinux 볼륨 마찰 회피, RAM 절약)
- `HTTP_ADDR = 127.0.0.1`, 포트 3000 (외부 노출은 터널 `git.<domain>` 경유만)
- 공개 가입 **비활성화**. 관리자 비밀번호는 서버 비공개 노트에만.
- 학생은 로컬 계정이라 루프백으로 Gitea 웹 UI 접근 가능 — 전제하고 권한 설계 (본인 저장소만 쓰기).
- 계정·저장소는 CSV 기준 일괄 생성 + 반별 `class-wiki` 2개.
- **credential store 사전 주입**: 각 학생 홈 `.git-credentials`에 개인 토큰 — push 때 비밀번호 안 물음 (SSH 키 배포보다 마찰 0).
- 각 학생 프로젝트 폴더 `git init` + remote 등록까지 완료 상태로 제공.
- **전역 gitignore** (`--system` 한 번):
  ```bash
  printf ".env\n*.key\n.codex/\n.gemini/\nnode_modules/\nharness\n.harness/\n" | sudo tee /etc/gitignore
  sudo git config --system core.excludesfile /etc/gitignore
  ```

## GitHub 이전 (수료 시 — 포트폴리오)

**질문**: Gitea로 관리하다 나중에 GitHub로 옮기면 커밋 이력·브랜치가 남는가?

**답: 커밋 이력은 완전히 남고, 설정은 남지 않는다.**

| 항목 | 이전되는가 | 방법·비고 |
|---|---|---|
| 커밋 이력 (author·날짜·메시지) | **예, 전부** | `git push --mirror` 한 줄. git 데이터는 플랫폼 무관 |
| 브랜치·태그 | **예, 전부** | mirror push에 포함 |
| branch protection rule | 아니오 | 플랫폼 설정이라 GitHub에서 다시 만든다 (수 분) |
| 이슈·PR | 아니오 | 우리 수업은 이슈·PR을 안 쓰므로 무관 |

**잔디(contribution graph)까지 살리려면 — 지금 해둬야 하는 것 하나**:
GitHub는 커밋의 author 이메일이 계정에 등록된 이메일과 일치할 때만 잔디에 찍는다.
계정 방침이 "학생 gmail 1개"로 확정됐으므로(120), **계정 생성 시 `git config user.email`을
학생 gmail로** 설정한다. 그러면 수료 후 학생이 그 gmail로 GitHub 계정을 만들어
mirror push 하는 순간 **12주치 잔디가 소급해서** 찍힌다. 고등부 포트폴리오 가치의 핵심.

수료 절차(12주차 "집에서 이어가는 법"에 포함): GitHub 계정 생성(gmail) → 새 저장소 →
`git push --mirror` → 프로필에 12주 이력·잔디 완성.
