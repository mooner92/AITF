## 0. 지금 상태 (정직하게)

설계만 있고 **코드는 없다.** 스크립트·cron·위키 내용 전부 비어 있으며,

## 1. 구조 — LLM Wiki 패턴 3층

패턴 문서의 Architecture 를 그대로 따른다. **핵심은 "매주 새 파일"이 아니라
"기존 페이지가 자란다"**는 것이다.

```
class-wiki-<반>/
  AGENTS.md              스키마 — LLM 을 위키 관리자로 만드는 설정 (materials/wiki-schema/)
  index.md               카탈로그 (마커 안 자동)
  log.md                 시간순 append — `grep '^## \[' log.md | tail -5`
  raw/<기수>-wNN.json     ① 원천. 결정적 수집, **불변**. LLM 도 읽기만 한다
  students/<계정>.md      ② 엔티티 — 학생 1인 1페이지가 12주간 자란다
  skills/<스킬>.md        ② 엔티티 — 스킬. 링크 그래프의 허브
  projects/<폴더>.md      ② 엔티티 — 프로젝트
  concepts/<개념>.md      ② 엔티티 — LLM 이 필요하다 판단하면 새로 만든다
```

### 마커 구간 — 이 설계의 심장

```
<!-- auto:활동 -->   스크립트가 매번 덮어씀 (사실)
<!-- /auto:활동 -->
그 밖              LLM·사람이 쓴 서술 — 스크립트가 보존
```

**모델이 없어도 사실은 쌓이고, 모델이 붙으면 서술이 자란다**가 동시에 성립한다.
검증: LLM 서술을 넣은 뒤 다음 주 자동 갱신을 돌려 서술이 살아남는 것을 확인했다.

### 활동 표는 raw/ 에서 재생성한다

이전 마크다운을 파싱해 누적하면 표 형식이 바뀔 때 구 형식 행이 남는다.
raw 가 불변 원천이므로 표는 **매번 raw 전체를 다시 읽어** 만든다 — 자기 치유적이다.

## 1-1. 옛 3층 구조 (폐기)

강사 요구: **학생별 · 반별 · 전체.** 저장소를 3층으로 나누지 않고,
**반 저장소 하나 안에서 3층을 만든다** — 수집은 한 번, 출력만 세 갈래.

```
high/class-wiki-high              ← 반 저장소 (반별 + 학생별을 함께 담는다)
  README.md                       반 인덱스: 주차 목록·학생 목록 (자동 갱신)
  weeks/w01.md                    ① 반별 — 그 주 반 전체에 무슨 일이
  students/<계정>/w01.md          ② 학생별 — 그 주 그 학생이 한 일
  students/<계정>/index.md        학생 누적 (12주 치 링크 + 합계)
  skills/<스킬>.md                누가 언제 썼나 — 7주차 그래프의 간선 재료

archive/class-archive             ← ③ 전체 — 반 구분 없는 수업 기록
  2026-fall/high/w01.md           반별 요약 사본 (계정 ID만, 실명 없음)
  2026-fall/mid/w01.md
```

> 아래는 최초 설계. 위 구조로 대체됐다.

**왜 학생별 저장소를 따로 안 만드나**: 학생이 5명이면 위키 저장소가 5개 더 늘고,
주마다 5번 커밋해야 하며, 7주차 그래프를 그리려면 5곳을 순회해야 한다.
같은 저장소 안 폴더면 **반당 커밋 1회**로 끝나고 그래프도 한 번에 읽는다.

**왜 Gitea 위키 기능(`.wiki`)이 아니라 일반 저장소 파일인가**

| | Gitea 위키 기능 | 일반 저장소 파일 (채택) |
|---|---|---|
| 폴더 구조 | 사실상 평면 | 3층 그대로 |
| 스크립트 | 별도 `.wiki.git` 를 따로 클론·푸시 | 저장소 하나만 다루면 됨 |
| 봇 RAG(150) | 접근 경로가 하나 더 | 파일 경로가 곧 검색 대상 |
| GitHub 이전 | 위키는 별도 취급 | `--mirror` 에 그대로 포함 |

Gitea 는 저장소 안 md 를 그대로 렌더링하므로 보기에도 차이가 없다.

## 2. 수집 → 생성 (한 번 돌면 3층이 함께 갱신)

```
일 20:00 cron
  → 반별로: 학생 순회하며 그날 활동 수집
      · git 커밋 (계정 project 저장소, 그날치 로그)
      · 만든 폴더 (모노레포 신규 디렉토리 = 그 주 프로젝트)
      · 쓴 스킬 (~/.codex/skills 접근 시각 또는 세션 로그)
      · 결과물 (/srv/pages/<계정> 변화)
      · 토큰 사용량 (/var/lib/tokmon/<계정>.json)
  → students/<계정>/wNN.md 생성 + index.md 갱신
  → weeks/wNN.md 생성 (반 요약: 누가 뭘 만들었나 한 줄씩)
  → skills/<스킬>.md 에 사용 기록 추가
  → README.md 인덱스 재생성
  → 반 저장소에 커밋 1회 push
  → archive 에 반별 요약 사본 커밋
```

**LLM 은 선택 요소다.** 뼈대(무엇을 했다)는 결정적 수집으로 만들고,
"이번 주 한 줄 총평" 같은 문장만 로컬 모델(150)에 맡긴다. 모델이 없거나
죽어도 위키는 계속 쌓인다 — **자동화의 생존을 LLM 에 걸지 않는다.**

## 2-1. 학생이 위키를 읽는 법 — 이 설계의 핵심 쓸모

프로젝트를 하다 막혔을 때 **먼저 찾아보는 곳**이 되게 한다. 경로 셋:

| 경로 | 방법 | 쓸모 |
|---|---|---|
| **파일 시스템** (주력) | `~/class-wiki` → `/srv/wiki/<반>` 심링크 | **Codex 가 직접 읽는다** — "위키 보고 참고해서 만들어줘" |
| 웹 | Gitea 의 반 저장소 | 링크로 공유·둘러보기 |
| 봇 | 가오리·거북이에게 질문 (150) | "지난주에 누가 급식봇 만들었지?" |

**파일 시스템 경로가 결정적이다.** 위키가 학생 홈에 실재하면 Codex 가
`~/class-wiki` 를 그냥 읽는다 — 무료 GPT 로는 절대 못 얻는 답("우리 반이
지난주에 뭘 만들었나")이 프로젝트 작업 중에 바로 나온다.

권한:

```
/srv/wiki/<반>   root:cls-<반>  750   ← 같은 반만 읽기, 아무도 쓰기 불가
~/class-wiki     → 심링크
```

- 리눅스 그룹 `cls-mid`·`cls-high` 로 반을 가른다 — **다른 반 위키는 읽히지 않는다**
  (120의 "반이 섞이면 집중이 깨진다"를 파일 권한으로 보장)
- 학생은 **읽기만** 된다. 위키는 생성기만 쓴다 — 장난·실수로 훼손될 수 없다
- 정본은 Gitea 저장소, `/srv/wiki` 는 생성 때마다 rsync 되는 사본

## 3. 개인정보

- **계정 ID만.** 실명은 위키에 넣지 않는다 (roster.csv 는 서버 전용)
- 다른 학생 파일 **내용**은 담지 않는다 — "무엇을 했다"는 사실만
- 반 저장소는 private, 열람은 해당 반 조직 팀만 (060에서 구성 완료)

쌓이지 않은 기간은 복구되지 않는다 — 그래서 A 가 개강 전 필수다.

## 5. GitHub 조직 이전 (수료 시)

**가능하다.** 조사 결과(2026-08-25):

| 항목 | 이전되나 | 방법 |
|---|---|---|
| 커밋 이력·브랜치·태그 | **예, 전부** | 조직에 빈 저장소 생성 → `git push --mirror` |
| 잔디(기여 그래프) | **예, 소급** | 커밋 author 이메일 = GitHub 계정 인증 이메일이면 자동 귀속 |
| 위키(일반 파일 방식) | **예** | 저장소 내용이라 mirror 에 포함 |
| 이슈·PR | 해당 없음 | 수업에서 안 씀 |
| branch protection | 아니오 | 플랫폼 설정 — 필요하면 재생성 |

**구조 대응**

```
GitHub Org (예: aitf-academy)
├── Team: high-2026   ← Gitea high 조직에 대응
├── Team: mid-2026
└── 저장소
    ├── high-2026-⟪계정⟫      학생 모노레포
    ├── high-2026-wiki        반 위키
    └── archive-2026-fall     전체 아카이브
```

**주의: GitHub 에는 저장소 폴더 계층이 없다.** 조직 안은 평면이고
Team 은 권한 그룹일 뿐이다. 반 구분은 **Team + 저장소 이름 접두사**로 낸다.

**포트폴리오 관점의 권고 — 학생 개인 계정에도 사본을 둔다.**
조직 저장소만 두면 학생이 조직에서 나가거나 조직이 사라질 때 접근을 잃는다.
수료 절차를 이렇게 한다:

1. 학생이 자기 gmail 로 GitHub 계정 생성 (이메일 인증까지)
2. **자기 계정에** 저장소 만들고 `git push --mirror` → 잔디·이력이 개인 프로필에 남는다
3. 조직에는 별도로 아카이브 사본 — 학원 자산·다음 기수 자료용

이 순서면 개인 포트폴리오(2)와 학원 아카이브(3)가 서로 독립적이다.

## 8. 커밋 의존성 — 중요

**위키 갱신은 커밋에 의존하지 않는다.** git 은 커리큘럼상 4주차에 배우므로
1~3주차에는 커밋이 **구조적으로 0건**이다. 커밋만 보면 첫 3주가 통째로 빈다.

수집 신호를 층으로 둔다:

| 신호 | 커밋 필요? | 언제부터 |
|---|---|---|
| 바꾼 파일 (`find -mtime`) | 아니오 | **1주차부터** — 1차 신호 |
| 만든 폴더 | 아니오 | 1주차부터 |
| 작품관 파일 수 | 아니오 | 1주차부터 |
| 설치된 스킬 | 아니오 | 1주차부터 |
| 커밋 메시지 | 예 | 4주차부터 — 부가 정보 |
| 미커밋 변경 수 | 예(저장소만) | 4주차부터 — "커밋 습관" 지표 |

실측 검증: 커밋 없이 폴더·파일만 만든 계정에서 "바꾼 파일 2 · 폴더 use_skills ·
작품 1"이 정상 기록되는 것을 확인했다.

**주의 — root 는 학생 저장소를 직접 읽을 수 없다.** git 이 dubious ownership 으로
거부해 커밋이 조용히 0건으로 기록되던 버그가 있었다. `sudo -u <계정>` 으로
소유자 권한으로 읽어 해결했다(읽기 전용).

## 9. LLM 보강 (`enrich-wiki.py`)

`raw/` 사실을 근거로 엔티티 페이지의 **마커 밖 서술**만 채운다.

- OpenAI 호환 엔드포인트 사용 — **OpenAI 종량제와 회사 로컬 모델 둘 다 동작한다**
  (`LLM_URL` 만 바꾸면 됨: `https://api.openai.com/v1` 또는 회사 서버)
- **출력 길이 파라미터가 갈리는 문제를 자동 처리한다.** OpenAI 최신 모델은
  `max_tokens` 를 거부하고 `max_completion_tokens` 를 요구하는 반면, 로컬 서버
  (vLLM·Ollama)는 대개 `max_tokens` 만 안다. 네 조합을 순서대로 시도해
  어느 쪽이든 통과시킨다. 일부 추론 모델의 `temperature` 커스텀 거부도 같은 방식
- 설정: `/opt/scripts/wiki-llm.env` (600). **미설정이면 아무것도 하지 않고 종료** —
  위키를 훼손하지 않는다
- 이미 사람이 쓴 서술은 덮어쓰지 않는다 (`--force` 로만)
- 프롬프트 제약: raw 에 **없는 내용 금지**, 학생 **비교·평가 금지**, 계정 ID만
- 실패해도 위키는 이미 완성돼 있다 — LLM 은 덤이지 의존 대상이 아니다
- **로컬 모델도 성능상 가능하다**(선택지로만): 이 서버에서 LFM2.5-2.6B Q4 실측
  생성 13.3 tok/s → 2~4문장 서술 1건에 약 15초. 일요일 20시 무인 실행이라
  느려도 무방하다. 다만 GPT 키가 있으면 굳이 쓸 이유는 없다 (150 부록·190 4-1)

검증(가짜 서버 4종으로 실행):

| 상황 | 결과 |
|---|---|
| `max_tokens`·`temperature` 둘 다 거부 (OpenAI 최신 모델 거동) | 폴백 성공 |
| `max_completion_tokens` 미지원 (로컬 서버 거동) | 폴백 성공 |
| 잘못된 키 (401) | 폴백 없이 즉시 중단, 위키 무변경 |
| 서버 꺼짐 (연결 거부) | 즉시 중단, 위키 무변경 |
| 설정 파일 미설정 | 아무것도 하지 않고 종료 |
