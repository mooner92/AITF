# 080 — P7: 스냅샷·복구 시스템 ★수업 운영의 안전망

**상태**: Draft · 차단: 040

## 목표

3단 안전망: ① 수업 후 반 단위 스냅샷(진행상황 보존) ② 학생 단위 복구(사고 대응) ③ 종강 후 아카이브·초기화.

## 설계

- **스냅샷**: `rsync -a --link-dest`로 이전 스냅샷과 하드링크 중복 제거 → 12주치 쌓아도 용량 증가 미미
  - 제외: `node_modules`(템플릿에 있어 복구 시 재충전), `.cache`, `.npm`
  - 스냅샷마다 `summary.md` 자동 생성: 학생별 커밋 수 / 누적 토큰 / 마지막 수정 파일 → 진도 파악
- **복구**: 스냅샷에서 학생 홈 복원 + 템플릿에서 node_modules 재충전 + chown
- **종강**: 스냅샷+토큰 데이터 tar 아카이브. 계정 삭제는 **자동 실행하지 않고** 명령을 출력만 — 육안 확인 후 직접 실행
- 전체 원상복구는 부트 볼륨 백업(010) 롤백이지만, **백업 이후의 다른 서비스 데이터도 함께 되돌아가므로 최후 수단**. 코스 사고는 반드시 이 스펙의 스크립트로 해결.
- 스크립트: [`scripts/snapshot-class.sh`](../scripts/snapshot-class.sh) · [`scripts/restore-student.sh`](../scripts/restore-student.sh) · [`scripts/reset-course.sh`](../scripts/reset-course.sh)
