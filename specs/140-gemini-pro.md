**상태** `Draft` — 결정 2건 대기
**전제** 강사가 개인 명의 Google AI Pro 구독 보유 (월 ₩29,000 / $19.99)

## 2. 판단의 기준선 — 개인 구독은 학생에게 공유하지 않는다

Claude 구독 건(120)과 **같은 결론**입니다.

- 약관상 계정 공유·제3자 사용 소지
- 6명이 쓰면 강사 본인의 한도를 수업이 잠식
- 학생 6명이 동시 접속하면 컴퓨트 한도가 순식간에 소진

→ **구독은 강사 도구로만 씁니다.** 학생이 쓰는 것은 각자 gmail의 무료 티어입니다.

---

## 3. 그래서 무엇이 달라지나 — 채택 3건

### ⓐ 8주차 AI 영상 — 조사 결과 "부분 해결"

**Flow 실태 (2026-08 확인)**

| 항목 | 값 |
|---|---|
| 한 번 생성 길이 | **8초** (4·6·8초 선택). 이건 Veo의 구조적 상한 |
| 크레딧 1,000으로 | Lite ~100편 · Fast ~50편 · Quality ~10편 |
| **일일 생성 한도** | **하루 약 3편** (AI Pro). 이월 안 됨 |
| 길게 만들기 | Extend로 7초씩 이어붙여 최대 ~148초 (횟수만큼 크레딧 소모) |

**"1,000크레딧이면 너무 짧지 않나"** — 크레딧보다 **일일 3편 한도가 먼저 막습니다.**
크레딧은 월 50~100편치가 있어도 하루 3편이면 수업 한 번에 3편이 상한입니다.

**그래서 결론**: 학생 6명이 각자 영상을 만드는 것은 **불가능**합니다.
**단체 세션 1~2편 시연**은 가능하고, 그 이상은 안 됩니다.

**개정된 8주차 방식**

1. **강사 시연 1~2편** — 학생들이 프롬프트를 제안하고 강사가 생성. 8초 클립 하나면
   "프롬프트가 영상을 바꾼다"를 보여주기에 충분합니다
2. **개인 영상은 기존 방식 유지** — 로컬 생성을 걸어두고 하교 → 9주차 공개.
   폐기하지 않고 이쪽이 **주(主) 경로로 남습니다**
3. 남는 시간은 자유 심화(v8.4 구성)로

**Flow는 "해결책"이 아니라 "시연 도구"입니다.** 앞선 판단을 정정합니다.

### ⓑ 11주차 "우리 위키를 아는 AI" → Gemini Notebook ★ 학생이 직접 한다

**현재 계획**: 위키를 AI에게 읽히는 체험 — 구현 방법이 미정이었습니다.

**Gemini Notebook은 RAG인가?** — **맞습니다.** 교과서적인 RAG 구조입니다:
업로드한 문서를 잘라 벡터로 만들어 저장 → 질문이 들어오면 관련 조각을 검색 →
그 조각만 근거로 Gemini가 답변 → **출처를 원문 위치로 링크**합니다.
학생이 "내가 올린 문서에 없는 건 답을 안 한다"를 눈으로 확인할 수 있어,
11주차에 RAG 개념을 설명하기에 이보다 나은 교보재가 없습니다.

**Gemini Notebook 무료 티어로 충분합니다.**

| 무료 티어 | 우리 필요 |
|---|---|
| 노트북 100개 | 학생당 1개 |
| 소스 50개/노트북 | 위키 문서 수십 개 |
| 하루 채팅 50회 | 수업 2시간에 충분 |
| Audio·Video Overview 포함 | 덤 |

**결정적 장점**: 학생이 **각자 gmail로 직접** 합니다 — 강사 시연이 아니라 본인 실습입니다.
자기가 12주간 쓴 위키를 올려 "우리 수업을 아는 AI"를 만드는 경험이 훨씬 강합니다.

**⚠ 나이 제한 — 만 13세 이상.** 개인 구글 계정 기준입니다.
중등 저학년 일부가 걸릴 수 있어, 해당 학생은 **짝 활동**으로 진행합니다
(계정 방침에서 이미 만 14세 미만 보호자 동의를 안내하고 있으므로 대부분 해소되지만,
13세 미만이면 계정 자체가 없으므로 짝으로 붙입니다).

### ⓒ 강사 준비 도구 — 수업 자료 제작

- **$10 Cloud 크레딧** — n8n 데모 워크플로의 Gemini API 호출에 사용 (서버 측, 학생 미노출)

## 5. 커리큘럼 방향 — "네 가지 AI를 직접 써본 아이"

강사 도구 활용보다 **이쪽이 본질**입니다. 학생은 gmail이 있으므로
**Gemini 무료 티어를 각자 쓸 수 있습니다.** 그러면 12주 동안 네 종류를 직접 다루게 됩니다.

| 종류 | 무엇 | 학생이 쓰는 방법 | 언제 |
|---|---|---|---|
| CLI 에이전트 | Codex | 학원 키 (계정별 상한) | 1주~ 상시 |
| 웹 챗봇 | ChatGPT · **Gemini** | 각자 무료 계정 | 2주~ 상시 |
| 로컬 모델 | qwen · gemma | `/compare` 봇 (서버) | 2주~ |
| 문서 AI (RAG) | Gemini Notebook | 각자 gmail | 11주 |

**이게 이 수업의 차별점이 됩니다.** 대부분의 AI 수업은 한 도구만 가르칩니다.
"GPT·Claude·Gemini·로컬 모델을 다 써보고 **일마다 골라 쓸 줄 아는 아이**"가 12주의 결과물입니다.

### 주차별 반영

| 주차 | 변경 |
|---|---|
| **2주** | 블라인드 테스트에 **Gemini 추가** — GPT · Gemini · 로컬 3파전. 학생이 각자 Gemini 웹을 열어 같은 질문을 던져보는 것까지 (무료 계정으로 가능) |
| **3주** | 발표자료 제작 시 **Gemini에도 같은 요청**을 해보고 결과 비교 (선택) |
| **5주** | **이미지 모델 비교** — Nano Banana Pro(강사 시연) vs Qwen 로컬. 포스터에 글자를 넣어 승부를 가른다 |
| **8주** | Flow는 **강사 시연 1~2편**으로 축소. 개인 영상은 로컬 걸어두기 유지 |
| **9주** | 리서치는 무료 챗봇에서 — **ChatGPT·Gemini 중 각자 편한 것** (이미 반영됨) |
| **10주** | **리마인드 회차 신설** (아래) |
| **11주** | 위키 RAG를 **Gemini Notebook 학생 실습**으로 확정 |

### 10주차에 "리마인드" 블록 추가 ★

**요청하신 핵심**: 프로젝트에 배운 것을 최대한 응용하게 하려면,
**배운 것을 한 번 펼쳐놓고 보는 자리**가 필요합니다.

10주차 도입 20분을 여기에 씁니다 (SDD 20분 앞):

> **"9주 동안 뭘 배웠지"** — 위키·작품관·Notion 주간 정리를 한 화면에 펼칩니다.
> 그리고 각자 자기 프로젝트에 대고 묻습니다:
> **"이 중에서 내 프로젝트에 쓸 수 있는 게 뭐지?"**
>
> 도구 목록을 표로 띄웁니다 — 모델 선택 · AGENTS.md · 스킬 · 내 봇 · MCP ·
> Playwright · 이미지 생성 · Notebook. 각자 **3개를 골라 적습니다.**
> 그것이 SDD 스펙에 그대로 들어갑니다.

**왜 10주차인가**: 9주에 설계했고 11~12주가 구현입니다.
이 자리에서 고른 3개가 남은 3주의 방향을 정합니다. 더 이르면 배운 게 부족하고,
더 늦으면 적용할 시간이 없습니다.

**자동 위키가 여기서 두 번째로 쓰입니다** — 7주차엔 "누가 뭘 했나"를 보는 용도였고,
10주차엔 **"내가 뭘 할 수 있나"**를 찾는 용도입니다.

## 결정 기록

- 2026-08-21 · Google AI Pro는 **강사 도구로만** 쓴다. 개인 구독의 학생 공유는 Claude 건(120)과
  같은 이유로 불채택. 학생은 각자 gmail 무료 티어를 쓴다.
- 2026-08-21 · **Flow에 대한 앞선 판단을 정정.** 일일 3편 한도 때문에 학생 개인 영상 제작은
  불가능하다. Flow는 해결책이 아니라 시연 도구이며, 8주차 개인 영상은 로컬 걸어두기가
  주 경로로 남는다.
- 2026-08-21 · Gemini Notebook이 **교과서적 RAG 구조**임을 확인(청킹·벡터 검색·근거 한정 답변·
  출처 링크). 11주차 RAG 교보재로 확정.
- 2026-08-21 · **수업의 축을 "네 종류 AI를 직접 써본다"로 정리.** CLI(Codex) · 웹 챗봇
  (ChatGPT·Gemini) · 로컬(qwen·gemma) · 문서 AI(Notebook). 학생 gmail로 Gemini가 무료로
  가능해져 성립한다.
- 2026-08-21 · **10주차에 리마인드 블록 20분 신설.** 배운 것을 펼쳐놓고 프로젝트에 쓸 3개를
  고르게 한다. 이 선택이 SDD 스펙에 그대로 들어가 남은 3주의 방향이 된다.
