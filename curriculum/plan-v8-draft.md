# 커리큘럼 v8 개편안 (검토용 초안)

> v7의 문제의식: **"결과물은 많은데 AI를 체계적으로 배우는 느낌이 없다."**
> v8은 축을 바꿉니다 — 매주 다른 걸 만드는 과정에서,
> **매주 AI 도구를 한 겹씩 더 깊이 다루는 과정**으로.
>
> 이 문서는 확정본이 아니라 논의용입니다. 합의되면 `detailed-plan.md`에 반영합니다.

---

## 1. 주신 피드백에 대한 답

### ① 1주차 분량 — 동의합니다. 다만 첫 주의 진짜 목표는 따로 있습니다

6명이면 늘어지지 않는다는 판단, 맞습니다. 다만 **접속 25분은 그대로 잡아두시길** 권합니다.
6명이라 빠른 게 아니라, 첫 접속은 인원과 무관하게 **한 명이 막히면 전체가 멈추는** 구조라
그렇습니다. 계정 오타 하나, 브라우저 캐시 하나가 10분을 먹습니다. 빨리 끝나면 명함 다듬기에
쓰면 되고, 이건 남는 시간이지 손해가 아닙니다.

"쉬엄쉬엄"에도 동의하는데, 이유를 하나 덧붙이고 싶습니다. **1주차의 진짜 산출물은 명함이
아니라 두 가지 데이터입니다.**

1. **각 학생의 1주차 기록** (소요 시간·토큰) — 12주차 개선률의 기준점. 이게 없으면 마지막
   주의 핵심 장치가 통째로 무너집니다
2. **학생별 속도 차 파악** — 짝 배치와 2주차 분량 조절의 근거

그래서 첫 주는 진도를 빼는 주가 아니라 **재는 주**입니다. 쉬엄쉬엄이 맞습니다.

**"첫 주 보고 다음을 준비한다"는 부분은 절반만 동의합니다.** 2~3주차는 그렇게 해도 됩니다.
하지만 **4주차 이후는 미리 준비해야 합니다** — 스킬 설치, 이미지 생성 비용 실측, Paseo 검증은
전부 서버 작업이라 수업 전날 되지 않습니다. 제안: **2~3주차는 유연하게, 5주차 이후 준비물은
개강 전에 확정.**

### ② 2주차가 loose하다 — 전적으로 동의합니다

지금 2주차("내 소개 웹페이지 만들기")는 **1주차의 연장**이지 새로운 배움이 없습니다.
말씀대로 1주차에서 터미널을 끝내고, 2주차부터 AI 본론으로 들어가는 게 맞습니다.

→ **2주차를 "Codex는 챗봇이 아니다"로 전면 교체합니다.** 아래 3절 참조.

### ③ Codex 구조·모델 비교·위키 — 채택. 다만 하나가 충돌합니다

전부 좋은 방향이고 v8의 뼈대로 넣었습니다. **위키는 특히 좋은 아이디어라 격상했습니다** —
단순 기록이 아니라 12주 내내 자라는 축으로 삼았습니다 (4절).

다만 짚어야 할 충돌이 있습니다. **현재 10주차에는 "9주 동안 쓰던 에이전트에 강사가 미리
설정을 넣어뒀다"는 서프라이즈 공개가 설계돼 있습니다.** 2주차에 Codex 구조를 설명하면
이 카드는 사라집니다.

**제 권고는 서프라이즈를 폐기하는 것입니다.** 이유 셋:

- 원하시는 방향("체계적", "본격적", "매주 성장을 직접 느끼는")과 서프라이즈는 상극입니다.
  9주간 감추는 설계는 그 9주 동안 학생이 도구를 자기 것으로 만들지 못하게 막습니다
- 구조를 일찍 알면 **3주차부터 학생이 자기 설정을 고칠 수 있습니다.** 이게 훨씬 큰 성장 경험입니다
- 부수 효과로 저장소 공개 문제도 해소됩니다 (그동안 미뤄둔 결정)

폐기하면 10주차 자리가 비는데, 거기에 **Paseo 설정 + 위임 개시**를 넣습니다 (6번 요청과 맞물림).

### ④ 할루시네이션 시연 — 지적이 맞습니다. 더 나은 방법이 있습니다

"없는 책 제목"은 최신 모델에서 잘 안 걸립니다. 정확한 지적입니다.
**세종대왕 맥북 사건보다 확실하고 강렬한 방법이 있습니다.**

> **사람 이름을 물어보게 하는 것입니다.**
> 강사 이름을 먼저 넣어 시연합니다 — "최명헌이 누구야?"
> 유명인이 아니면 모델은 거의 100% 그럴듯한 인물 설명을 지어냅니다.
> 그다음 **원하는 학생만** 자기 이름을 넣어보게 합니다.

세종대왕 사례보다 나은 이유: ⓐ 재현율이 사실상 100% ⓑ 남의 옛날 이야기가 아니라
**방금 내 눈앞에서** 일어남 ⓒ "AI는 모르면 모른다고 하지 않는다"가 즉시 체감됩니다.

세종대왕 사례는 **백업 슬라이드**로 둡니다. 다만 스크린샷을 그대로 쓰기보다 출처를 밝히고
**인용으로 재현**하는 편이 안전합니다 — 남의 화면 캡처는 출처가 불분명한 것이 돌아다닙니다.

### ⑤ 나만의 스킬 만들기 — 채택, 독립 주차로 승격

v7에서는 고등반 과제로만 있었습니다. **6주차를 통째로 여기에 씁니다** (중등반 포함).
"남의 스킬을 쓴다(5주) → 내 스킬을 만든다(6주)"의 순서가 성장 실감의 핵심 구간입니다.

### ⑥ 자발적 탐색·에이전틱·Paseo — 전부 채택

- **매주 마지막 5분을 "이번 주에 나온 것"으로 고정**합니다. 강사가 1~2개 소개하고,
  본 게 있는 학생은 공유합니다. 숙제가 아니라 습관을 심는 자리입니다
- **Playwright(에이전틱)를 7주차로** 독립시킵니다
- **Paseo는 10주차 설정 → 11~12주 집중 구현**으로 배치합니다

## 2. 무엇이 바뀌나 (v7 → v8)

| | v7 | v8 |
|---|---|---|
| 축 | 매주 다른 **결과물** | 매주 더 깊은 **도구 이해** (결과물은 그 부산물) |
| 2~3주 | 웹페이지 만들기, 지시문 실험 | **Codex 구조**, **모델 비교** |
| 스킬 | 4~7주 "갖다 쓰기"만 | 5주 **쓰기** → 6주 **만들기** |
| 에이전틱 | 없음 | 7주 **Playwright** |
| 기록 | 작품관(전시) | 작품관 + **위키**(지식 축적) |
| 10주 | 서프라이즈 공개 | **Paseo 설정 + 위임 개시** (공개는 2주로 앞당김) |
| 자발적 탐색 | 없음 | **매주 5분 고정 코너** |
| git | 6주 | **4주** (설정을 고치다 망가뜨릴 때가 진짜 필요한 시점) |

**유지되는 것**: 12주 구조, 주간 완결, 숙제 없음, 발표·시상 없음,
1주차 기준점 → 12주차 개선률 측정, 작품관, 중등/고등 갈래.

## 3. 주차별 개편안

### 1주 — 터미널과 첫 대화 *(터미널 여기서 완결)*

| | |
|---|---|
| 도구 목표 | 접속 · tmux 3키 · Codex CLI 첫 대화 |
| 결과물 | 터미널 명함 |
| 측정 | **1주차 기준점 기록** (소요 시간·토큰) |

강사 소개 → 학생 이름 듣기(가볍게, 한 사람 15초) → 접속 → tmux → 명함 →
**할루시네이션 시연(이름)** → 사용량 그래프 = 기준점 → 위키 예고.

> 터미널 관련 내용은 이 주에 끝냅니다. 2주차부터는 도구로만 씁니다.

### 2주 — Codex는 챗봇이 아니다 ★

| | |
|---|---|
| 도구 목표 | CLI 에이전트의 구조. ChatGPT 웹과 무엇이 다른가 |
| 결과물 | 내 웹페이지 (인터넷에 실제로 뜸) |
| 신규 | **위키 개설** |

**핵심 실습 — 같은 요청을 둘에 던진다**

| | ChatGPT 웹 | Codex CLI |
|---|---|---|
| 결과 | 코드를 **보여준다** | 파일을 **만든다** |
| 다음 할 일 | 복사 → 붙여넣기 → 저장 | 없음. 이미 저장됨 |
| 내 컴퓨터를 | 모른다 | **읽고 쓴다** |

이 차이를 말로 설명하지 않고 **나란히 놓고 직접 해보게 합니다.**
"왜 굳이 까만 화면에서 하나"에 대한 답이 여기서 나옵니다.

**학생 페이지 웹 경로 — 여기서 처음 공개** (질문 주신 부분, 상세는 5절)

`~/project/public/` 에 파일을 넣으면 곧바로 `<주소>/pages/<내계정>/` 에서 열립니다.
학생이 만든 `index.html` 이 **30초 안에 인터넷에 뜨는 것**을 보는 게 이 주의 정점입니다.

**AGENTS.md 첫 대면** — "AI에게 매번 말하지 않아도 되게, 미리 적어두는 지시서".
읽기만 합니다. 고치는 건 4주차.

### 3주 — 모델을 고른다

| | |
|---|---|
| 도구 목표 | 모델별 차이 · 비용 구조 · 언제 큰 모델을 쓰나 |
| 결과물 | **위키: 모델 비교표** (학생이 만든 첫 지식 문서) |

같은 문제를 작은 모델(luna)과 큰 모델(terra)에 각각 던져 결과와 비용을 비교합니다.
Claude 계열은 강사가 시연으로 비교합니다.

- 토큰 → 돈. 사용량 그래프에서 방금 쓴 것을 확인
- **판단 기준을 스스로 만들게 합니다**: "이럴 땐 큰 모델, 이럴 땐 작은 모델"
- 고등: 컨텍스트 길이가 비용에 미치는 영향까지

### 4주 — 지시문과 설정, 그리고 되돌리기

| | |
|---|---|
| 도구 목표 | 좋은 지시문 4요소 · **AGENTS.md 직접 수정** · git 3동작 |
| 결과물 | 내 규칙이 들어간 에이전트 |

2주차에 읽기만 했던 `AGENTS.md`를 **직접 고칩니다.** 한 줄 바꾸고 결과가 달라지는 것을
확인하는 순간이 "도구가 내 것이 되는" 지점입니다.

**git이 여기 오는 이유**: 설정을 고치다 망가뜨릴 수 있어야 되돌리기가 절실해집니다.
6주차에 "작품을 지키자"고 도입하는 것보다 동기가 훨씬 강합니다.

### 5주 — 남의 스킬을 갖다 쓴다

| | |
|---|---|
| 도구 목표 | 스킬 = 지시가 적힌 텍스트 파일 · 설치와 사용 |
| 결과물 | 포스터/이미지 + 발표 슬라이드 |
| 신규 | **Claude Skill Market · GitHub 둘러보기** |

스킬 파일을 열어 읽는 것부터 시작합니다(v7의 "스킬 해부"를 여기로 앞당김).
그다음 이미지 생성 스킬과 슬라이드 스킬을 실제로 씁니다.

> 5주차 슬라이드는 **학교 수행평가에 쓸 수 있는 수준**이라는 v7의 실용 정점은 유지합니다.

### 6주 — 나만의 스킬 만들기 ★

| | |
|---|---|
| 도구 목표 | 반복 작업 발견 → SKILL.md 작성 → 테스트 → 수정 |
| 결과물 | **내 이름이 붙은 스킬** |

"내가 매번 똑같이 시키는 게 뭐지?"에서 출발합니다. 만든 스킬을 **서로 바꿔 써보고**
남의 스킬이 내 상황에서 안 먹히는 이유를 찾습니다 — 지시문의 한계를 몸으로 아는 자리.

### 7주 — 도구를 쓰는 AI (에이전틱)

| | |
|---|---|
| 도구 목표 | **Playwright** — AI가 브라우저를 직접 조작 |
| 결과물 | 웹에서 자료를 모아 정리한 페이지 |

AI가 "글을 쓰는 것"에서 "**일을 하는 것**"으로 넘어가는 주차입니다.
브라우저를 열고, 스크린샷을 찍고, 정보를 모읍니다.

**같이 다룰 것**: 왜 위험한 명령은 승인을 받아야 하는가. 자동화의 한계선.

### 8주 — 영상 + 작품관 완성 *(버퍼)*

이미지 시퀀스 → 영상 변환. 작품관 정리와 README. **밀린 주차 보충.**

### 9주 — 프로젝트 설계

주제 선정, 작업 분해표("AI에게 맡길 일 / 사람이 할 일"), 위키에 설계서 작성.

### 10주 — Paseo 설정 + 위임 개시 ★

| | |
|---|---|
| 도구 목표 | 여러 에이전트를 동시에 지휘하는 구조 (데몬·클라이언트) |
| 준비 | **학원 IP 등록 · 서버 상시 구동 설정** |

첫 작업을 걸어두고 하교합니다. 주중에 진행 상황을 볼 수 있습니다(선택).

### 11주 — 구현 집중

걸어둔 작업 검수 → 지시 보강 → 재위임. **위임의 질 = 지시의 질**을 비동기로 재확인.

### 12주 — 완성과 측정

1주차 과제 재도전 → **개선률 산출** → 프로젝트 완성 → 위키 최종 정리 → 수료.

## 4. 12주를 관통하는 세 갈래

주차 내용과 별개로 **매주 반복되는 것**입니다. 성장 실감은 대부분 여기서 나옵니다.

### 갈래 A — 위키 (신규, 매주 10분)

수업 내용과 자기 진행 상황을 학생이 직접 기록합니다. 강사가 주는 요약본이 아니라
**학생이 쓰는 문서**라는 점이 핵심입니다.

| 시점 | 위키에 쌓이는 것 |
|---|---|
| 2주 | 개설. "Codex와 ChatGPT 차이" |
| 3주 | **모델 비교표** |
| 4주 | 내 프롬프트 모음 · 내 AGENTS.md 설명 |
| 5주 | 써본 스킬 평가 |
| 6주 | **내가 만든 스킬 문서** |
| 7주 | 자동화 기록 |
| 9주 | 프로젝트 설계서 |
| 12주 | 12주 학습 기록 = **포트폴리오의 절반** |

**왜 좋은가**: ⓐ 복습 자료 문제가 저절로 해결됩니다(학생이 쓴 것이 곧 복습본)
ⓑ AI가 읽기 좋은 문서를 쓰는 훈련 — 하네스 엔지니어링의 기초 그 자체
ⓒ 나중에 이 위키를 **RAG 자료로 삼아 "우리 수업을 아는 AI"를 만들 수 있습니다**(11주 소재)

### 갈래 B — 이번 주에 나온 것 (매주 마지막 5분)

숙제를 없앤 자리에 **습관**을 넣습니다. 강사가 1~2개를 짧게 소개하고, 본 게 있는 학생은

## 5. 학생 페이지 웹 경로 (질문 주신 부분)

**한 줄 요약**: 학생이 `~/project/public/` 에 파일을 넣으면 즉시 인터넷에서 열립니다.

```
학생이 터미널에서              실제 서버 위치            브라우저에서
~/project/public/index.html → /srv/pages/mid01/    → <주소>/pages/mid01/
        (심링크)                (nginx가 읽는 곳)
```

**왜 홈 디렉토리를 직접 열지 않았나**

학생 홈은 `700`(본인만 접근)으로 잠겨 있습니다. `.bashrc` 같은 파일에 API 키가 들어가기
때문에 홈을 웹에 열면 그게 그대로 노출됩니다. 그래서 **공개해도 되는 폴더를 따로 만들고**
(`/srv/pages/<계정>`, 755) 학생 홈에서는 심링크로 연결했습니다.
학생 입장에서는 그냥 `public` 폴더에 넣는 것이고, 나머지는 안 보입니다.

**수업에서 어떻게 쓰나**

- 2주차: 첫 `index.html` → 30초 안에 인터넷에 뜨는 경험
- 매주: 그 주 결과물을 여기에 전시
- 8주차: 작품관으로 정리, 공유 링크 확정
- 안전장치: 디렉토리 목록 보기 꺼짐, 숨김 파일 차단, 다른 학생 폴더 접근 불가

## 6. 자료 공유 (제안)

말씀하신 방식에 동의합니다. 다만 **한 곳만 공지**하는 게 좋겠습니다.

```
수업 슬라이드(HTML) + 복습 요약  →  노션 페이지  →  링크만 오픈채팅 공지
```

- 오픈채팅에 파일을 직접 올리면 버전이 흩어집니다. **노션 한 페이지를 계속 갱신**하고
  링크는 고정하는 편이 낫습니다
- 복습 요약은 강사가 새로 쓰지 말고 **슬라이드 발표자 노트에서 뽑아 씁니다**(이미 적혀 있습니다)
- 학생 위키와 역할이 다릅니다: 노션 = 강사가 주는 것, 위키 = 학생이 쓰는 것
