3 · 자동 위키

학생이 만든 것이
매주 저절로 쌓입니다

수업이 끝나고 일요일 20시, 서버가 그날 각 학생이 한 일을 문서로 만들어 위키에 넣습니다. 학생별 문서와 행위별 문서를 나눠 만들고, 서로 링크로 엮습니다.

수업 종료 18:00→ 20:00 자동 수집→ 학생별 · 행위별 md 생성→ 위키 그래프 갱신→ Notion 주간 페이지 발행→ Slack #위키 알림

정본은 서버 위키(Gitea)이고, Notion은 읽기 좋은 발행본입니다 — 학생·학부모가 링크 하나로 그 주 수업 내용을 복습합니다. 복습 자료를 강사가 따로 만들지 않습니다.

같은 스킬을 쓴 사람끼리 이어집니다

7주차에 공개합니다

1~6주 동안은 조용히 쌓기만 하고, 7주차 도입 15분에 처음 보여줍니다. 5주차 스킬 사용과 6주차 자작 스킬까지 반영돼야 연결선이 의미를 갖기 때문입니다. 더불어 7주차 주제가 에이전틱(AI가 도구를 써서 일을 하는 것)인데, "이 위키를 매주 AI가 자동으로 써왔다"는 사실 자체가 그 주제의 실물 예시가 됩니다.

개인정보 취급

위키에는 계정 ID만 들어갑니다(실명 없음). 다른 학생의 파일 내용은 담지 않고 "무엇을 했다"는 사실만 기록합니다. 반 내부에서만 열람하며 외부 공개하지 않습니다.

중등반

진행 · 도입 15분 — 위키 공개

6주 동안 쌓인 위키를 처음 보여줍니다. 누가 무엇을 했는지, 같은 스킬을 쓴 사람끼리 어떻게 이어져 있는지 함께 봅니다. 그리고 밝힙니다 — "이걸 매주 AI가 자동으로 써왔습니다."

진행 · 본 내용

그 자동화가 바로 오늘의 주제입니다. AI가 "글을 쓰는 것"에서 "일을 하는 것"으로 넘어갑니다 → 각자 Gemini 무료 API 키 발급 — "API 키가 무엇인가, 왜 비밀인가" (공개 폴더·git에 넣지 않는다는 규칙과 함께) → Playwright로 브라우저 열기·스크린샷·정보 수집 → 모은 자료를 페이지로 정리 → 위험한 명령은 왜 승인을 받아야 하는가 토론.

내 Slack 봇 기획 — 이 주의 백미

강사 예시(아침 브리핑 봇: 매일 9시 → 날씨 → 한 줄 브리핑 + 그림 → Slack)를 보여준 뒤, "너라면 Slack에 뭘 만들고 싶은가"를 각자 기획합니다. 우리 동네 버스 도착 알림(공공데이터포털 무료 API), 급식 메뉴, 날씨 옷차림, 좋아하는 게임 패치 소식 — 트리거 → 데이터 → AI 가공 → Slack 알림의 4단 구성만 지키면 소재는 자유입니다. 만든 봇은 수업이 끝나도 매일 돌아갑니다 — "내가 만든 게 계속 돌아간다"가 남습니다.

구현 재료

n8n(서버 셀프호스트, 무료) 또는 Playwright + 크론. 공공데이터포털 API 키는 무료지만 발급에 하루쯤 걸릴 수 있어 강사가 수업 전 공용 키를 미리 확보해 둡니다. 완성까지 못 가도 됩니다 — 기획서 + 절반 동작이면 성공이고, 나머지는 프로젝트 주간의 재료가 됩니다.

공개를 7주차에 두는 이유

5주차 스킬 사용과 6주차 자작 스킬까지 반영돼야 연결선이 의미를 갖습니다. 더불어 자동 위키 자체가 오늘 배울 에이전틱의 실물 예시라 도입과 본 내용이 하나로 이어집니다.
