무엇이 다른가

2026년 현재 개발 현장의 표준 작업 방식이 바로 이것입니다 — 터미널에서 AI 에이전트에게 일을 시키고, 결과를 검증하고, 버전 관리로 기록하는 흐름. 이 수업을 마친 학생은 실무 개발자가 매일 쓰는 것과 동일한 환경을 12주간 몸에 익힌 상태가 됩니다.

줄거리 5장면 설계 → 장면별 삽화 생성(4주차 프롬프트 역량 재사용 — 스타일 통일이 이번 주 도전) → 스킬로 책 형태 조립 → git 도입: "작품이 쌓이니 이제 기록합니다" — 사물함(저장소)·세이브(commit)·업로드(push) 비유, 3줄 실습 → 이야기책이 첫 공식 커밋이 됨.

중등반

창작 이야기 중심. git은 비유와 3줄 실습까지만 — status·log는 강사 화면으로 함께 읽고 넘어갑니다.

고등반

git status·log를 직접 읽고 커밋 메시지를 스스로 씁니다. 자작 스킬 과제 시작 — "네가 반복하는 작업을 도구로 만들어라" (8주까지).

교육 포인트

git을 "배워야 할 것"이 아니라 "내 작품을 지키는 도구"로 도입합니다. 이후 매주 마무리 = 커밋. 계정·저장소·연결은 전부 사전 세팅되어 학생은 3줄만 칩니다.

강사 준비

스토리북 스킬 제작·테스트, git 비유 슬라이드.
