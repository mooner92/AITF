## 1. 수업 정체성

겉으로 보이는 결과물은 그림·발표자료·영상이지만, 매주 실제로 늘어나는 것은
**AI 도구를 다루는 깊이**입니다. 2주차에 도구의 구조를 알고, 4주차에 설정을 직접 고치고,
6주차에 자기 도구를 만듭니다. 이 세 지점을 지나면 학생은 AI를 "주어진 대로 쓰는 것"이
아니라 "고쳐 쓰는 것"으로 대하게 됩니다.

커리큘럼은 고정판이 아닙니다 — **주차별 목표는 고정, 재료는 그 달의 최신 도구로 교체**.
교체는 직전 주까지 결정하고 서버 검증 후 투입합니다.

## 2. 관통하는 세 갈래 (매주 반복)

| 갈래 | 시점 | 내용 |
|---|---|---|
| 내 기록 | 첫 5분 | 대시보드에서 지난주 자기 기록 확인. 순위표 없음 |
| 위키 | 10분 | 학생이 직접 기록 + 수업 후 자동 생성분 |
| 이번 주에 나온 것 | 마지막 5분 | 새 소식 1~2개. 숙제 대신 습관 |

## 3. 자동 위키 → Notion 발행

일요일 20시, 서버가 그날 활동(커밋·스킬·설정 변경·결과물·사용량)을 수집해
학생별·행위별 md를 만들고 그래프를 갱신한 뒤 **Notion 주간 페이지로 발행**하고
Slack `#위키`에 알립니다. 같은 스킬을 쓴 학생끼리 스킬 노드를 매개로 이어지고,
6주차 자작 스킬은 새 노드로 갈라져 나옵니다. **7주차 도입 15분에 처음 공개**합니다 —
"이걸 매주 AI가 자동으로 써왔다"가 그 주 주제(에이전틱)의 실물 예시가 됩니다.
계정 ID만 기록하고 반 내부만 열람합니다.
그래프는 **서버 웹페이지로 시각화**합니다 — 노드를 드래그하고 클릭하면 해당 문서로 이동.
7주차 공개 때 이 화면을 프로젝터에 띄우는 것이 공개 장면 그 자체입니다.

## 4. 수업 환경

| 구성 요소 | 설명 |
|---|---|
| 준비물 | 학생당 **구글 계정 1개** (개강 전 준비, 만 14세 미만 보호자 동의). 그 외 없음 |
| 접속 | 학원 PC에서 SSH(계정 카드의 아이디·비밀번호) — Warp 또는 PowerShell. 학원 IP에서만 비밀번호 로그인 |
| 서버 | 학생별 독립 계정 (파일 격리, 관리 권한 없음) |
| 학생 페이지 | `~/project/public/` → `<주소>/pages/<계정>/` 즉시 공개 |
| 학생 웹서비스 | 9주차부터. 계정별 포트 100개 대역 + `mid01.<도메인>` 서브도메인 |
| 외부 접속 | 10주차 개방 — gmail 일회용 코드(24h 세션). 그 전에는 학원에서만 |
| 소통 | Slack (#질문·#작품·#모델비교·#위키). 학부모는 기존 학원 채널 |
| 모델 비교 봇 | `/compare` — 로컬 모델(qwen·gemma)과 GPT의 답·속도·비용 병기 |
| 위키·복습 | Gitea 위키(정본) → Notion 주간 발행 |
| 비용 통제 | 계정별 AI 상한, 이미지 주당 장수 제한 |
| 백업 | 매 수업 후 전원 스냅샷 |

공통 시간 골격(2시간, v8.6 개정): 내 기록 5분 → 시연 10분 → **실습 블록 3~4개 (85분,
블록당 20~30분)** → 휴식 10분(실습 사이) → 전시·커밋·위키 10분 → 이번 주에 나온 것 5분.
개강일 실측(설명 슬라이드 27장 = 40분 소진)에 따라 설명·시연은 10분 상한으로 줄이고,
나머지는 전부 학생 손이 움직이는 실습 블록으로 채운다. 슬라이드는 실습 블록마다
**입력할 명령어 · 성공 확인(체크포인트) · 빨리 끝낸 학생용 심화**가 박힌 지시형 화면으로
만들고, 학생이 따라 하는 동안 그 장에 머문다.

**중등·고등은 같은 내용으로 진행합니다** — 터미널 환경은 어느 쪽도 처음이라 출발선이
같습니다(1교시 고등 7명, 2교시 중등 6명). 중등반은 실습 블록을 더 잘게 쪼개고, 빨리 끝낸
학생에게 심화 과제를 줍니다. 심화 과제는 "시간 남으면"이 아니라 **모든 블록에 기본
내장**한다 — 준비량 기준은 실제 소화량의 5배.

위임 2회 이상. 체크포인트: 적용 전/후 스크린샷 비교. 심화: design.md를 cat으로 열어
바꾸고 싶은 줄 하나 찾아 직접 고쳐 재적용.
**진행 · 실습 4 — 공개 (20분)**: public/에 넣는 순간 30초 안에 인터넷에 → 폰으로 자기
주소 열어 확인 → **학교 제출 시 AI 활용 표기** 지도 → 위키 개설·기록(2주차에서 이월된
"우리 반 모델 가이드" 첫 문서 포함). 체크포인트: 자기 폰에서 자기 발표자료가 열리면 성공.
심화: 짝의 주소를 열어 좋은 점 하나 Slack #작품에 남기기.
**"선생님 자료는 왜 늘 비슷해 보여요?"** — 이 질문이 나오면 **강사가 쓰는 발표자료 스킬을
그대로 공개**한다(`/opt/harness/skills/deck/`). 색·글꼴을 매번 정하지 않고 규칙으로 고정해
뒀다는 것을 파일로 보여주는 자리 — 감각이 아니라 규칙. 원고(example.md)와 결과(example.html)를
나란히 놓으면 "글을 쓰면 자료가 나온다"가 한눈에 보인다. 희망 학생은 그대로 가져다 쓴다.
**강사 준비**: design.md 2~3종(스타일 다르게), 주제 제공 목록, 작품관 템플릿, 페이지 경로 확인,
발표자료 스킬 배포 확인.

"AI 말이라 검증 필요"한 대목에 표시(1주차 습관의 실전).

분해표 첫 줄을 Codex에 위임, 자기 포트에 첫 화면. 체크포인트: 서브도메인에서 프로젝트
첫 화면이 열리면 성공. 심화: Playwright 스크린샷 1장을 미리 남겨 "0일차 증거" 확보.
**강사 준비**: 주제 목록, 분해표 양식, 포트 배정·nginx 블록·MY-SERVER.md 배포
(alloc-ports.sh --deploy), 오프라인 안내 페이지 가동.

### 10주 — Paseo 설정 + 위임 개시 ★불가침

| | |

**진행 · 실습 1 — 리마인드 (20분)**: 위키·작품관·주간 정리를 한 화면에 펼치고 각자 묻는다:
"이 중에서 내 프로젝트에 쓸 수 있는 게 뭐지?" 도구 목록(모델 선택·AGENTS.md·스킬·내 봇·

수 있나". 체크포인트: 도구 3개 + 각각 "어디에 쓸지" 한 줄. 심화: 위키 그래프에서 같은
도구를 쓴 다른 학생을 찾아 방법 물어보기.
**진행 · 실습 2 — 스펙 승격(SDD) (25분)**: 분해표를 "무엇이 되면 완성인가"가 적힌 스펙으로
승격. 이 수업의 서버 자체가 스펙 문서(specs/)로 만들어졌음을 실물로 보여준다. 체크포인트:
스펙에 완성 기준이 검증 가능한 문장("~가 뜨면")으로 3개 이상. 심화: 짝 스펙을 읽고 "이대로
만들면 뭐가 나올지" 설명 — 설명이 갈리면 스펙이 모호한 것.
**진행 · 실습 3 — Paseo 위임 (35분)**: "이제 관리합니다" → Paseo 접속 → 대시보드 화면
읽기(작업 목록·상태) → 스펙의 첫 작업 걸어두고 → 두 번째 작업까지 큐에 → 하교. 체크포인트:
걸어둔 작업이 "진행 중" 상태로 보이면 성공. 심화: 서로 다른 모델로 같은 작업을 두 개 걸어
다음 주에 비교.
**진행 · 주중**: **10주 수업 끝~11주 수업까지 Slack #프로젝트에서 주중 작업·피드백**
(참여 선택, 강사가 스레드로 피드백). 학원에서는 인증 없이, 집에서는 gmail 코드로.
**강사 준비**: 학원 IP 등록, 데몬 메모리 실측(개당 ~520MB, 상한 조정), 동시 6명, 상시 구동,
페어링 절차·동의 문구, DNS 레코드·Access 정책(OTP 24h)·검증 7항(specs/110).

### 11주 — 위임과 검수

| | |
|---|---|
| **만들기 목표** | 프로젝트 중간 결과 + 개선 체크리스트 |
| **개발 역량** | 위임 → 자리 비움 → 검수 사이클, 개선 레버 3종(지시문/설정/스킬화) |
| **사용 기술** | "우리 위키를 아는 AI" 체험 — 쌓인 위키를 AI에게 읽히기 |

**진행**: 위임 → 자리 비움 → 검수 사이클을 하루 안에 두 바퀴 돌린다.
**진행 · 실습 1 — 주중 원격 작업 리뷰 (20분)**: Slack에서 오간 작업·피드백 팀별 확인 →
지난주 걸어둔 작업 결과를 스펙의 완성 기준과 대조(통과/실패 표시) → 방향 재설정 →
재위임(1바퀴째). 체크포인트: 완성 기준 대조표 작성 + 다음 작업이 큐에 걸림. 심화: 실패
항목의 원인을 지시문 문제/스펙 문제/모델 한계로 분류.
**진행 · 실습 2 — 자리 비우기 (40분)**: 재위임한 작업이 도는 사이에 — ① **README·문서
구조화**(남이 봐도 읽히게. 체크포인트: 짝이 README만 읽고 프로젝트를 설명할 수 있으면
통과) ② 위키 RAG 체험 — 각자 gmail로 **Gemini Notebook**(교과서적 RAG: 청킹→벡터 검색→
근거 한정 답변→출처 링크)에 자기 위키를 올려 직접 만든다(무료 티어로 충분, 만 13세 이상.
미만은 짝 활동. 체크포인트: 내 위키 내용을 근거로 한 답 + 출처 링크가 뜨면 성공. 심화:
위키에 없는 걸 물어 "모른다"가 나오는지 검사 — 근거 한정의 증명) ③ 개선 레버 3종(지시문/
설정/스킬화) 정리 — 내 프로젝트에서 각 레버를 쓸 곳 하나씩.
**진행 · 실습 3 — 재검수 (30분)**: 돌아와서 2바퀴째 검수 — 결과 대조 → 통과분 반영 →
12주 발표 준비 확인(스프린트 과제 예고). 체크포인트: 프로젝트가 지난주보다 완성 기준
n개 이상 전진했는지 숫자로 확인. 심화: Playwright로 회귀 스크린샷 찍어 지난주와 비교.
