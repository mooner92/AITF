## 1. 수업 정체성

겉으로 보이는 결과물은 그림·발표자료·영상이지만, 매주 실제로 늘어나는 것은
**AI 도구를 다루는 깊이**입니다. 2주차에 도구의 구조를 알고, 4주차에 설정을 직접 고치고,
6주차에 자기 도구를 만듭니다. 이 세 지점을 지나면 학생은 AI를 "주어진 대로 쓰는 것"이
아니라 "고쳐 쓰는 것"으로 대하게 됩니다.

커리큘럼은 고정판이 아닙니다 — **주차별 목표는 고정, 재료는 그 달의 최신 도구로 교체**.
교체는 직전 주까지 결정하고 서버 검증 후 투입합니다.

## 2. 관통하는 세 갈래 (매주 반복)

| 갈래 | 시점 | 내용 |
|---|---|---|
| 내 기록 | 첫 5분 | 대시보드에서 지난주 자기 기록 확인. 순위표 없음 |
| 위키 | 10분 | 학생이 직접 기록 + 수업 후 자동 생성분 |
| 이번 주에 나온 것 | 마지막 5분 | 새 소식 1~2개. 숙제 대신 습관 |

## 3. 자동 위키 → Notion 발행

일요일 20시, 서버가 그날 활동(커밋·스킬·설정 변경·결과물·사용량)을 수집해
학생별·행위별 md를 만들고 그래프를 갱신한 뒤 **Notion 주간 페이지로 발행**하고
Slack `#위키`에 알립니다. 같은 스킬을 쓴 학생끼리 스킬 노드를 매개로 이어지고,
6주차 자작 스킬은 새 노드로 갈라져 나옵니다. **7주차 도입 15분에 처음 공개**합니다 —
"이걸 매주 AI가 자동으로 써왔다"가 그 주 주제(에이전틱)의 실물 예시가 됩니다.
계정 ID만 기록하고 반 내부만 열람합니다.

## 5. 주차별 상세

### 1주 — 터미널과 첫 대화

| | |
|---|---|

tmux 3키 → 세션 지속 시연 → 첫 프롬프트로 명함 → 할루시네이션 시연(사람 이름으로 —

**강사 준비**: 완성 예시, 치트시트 인쇄, 계정 카드(서버+Slack), gmail 미준비 학생용 예비 계정.
**고등 추가**: 명함에 관심 분야 — 포트폴리오 첫 줄. 토큰 개념 구체화.

### 7주 — 도구를 쓰는 AI ★위키 공개

| | |
|---|---|
| **만들기 목표** | 웹에서 모은 자료를 정리한 페이지 |

**진행**: 도입 15분 — 6주 쌓인 자동 위키 공개 + "이걸 매주 AI가 써왔다" → 그 자동화가 오늘

봇) 시연 후 "너라면 Slack에 뭘 만들고 싶은가" — 버스 도착 알림(공공데이터포털), 급식 메뉴,

동작이면 성공, 나머지는 프로젝트 주간 재료 → 위험 명령 승인 토론.
**강사 준비**: Playwright 6명 부하 실측, 금지 사이트 목록, 위키 공개 화면, 키 발급 시연,
n8n 셀프호스트 + 브리핑 봇 예시, **공공데이터포털 공용 키 사전 발급**(하루쯤 걸림).
**고등 추가**: 수집 대상 자율 설계, robots.txt·이용약관 경계.

수업까지 Slack #프로젝트에서 주중 작업·피드백** (참여 선택, 강사가 스레드로 피드백).
학원에서는 인증 없이, 집에서는 gmail 코드로.
**강사 준비**: 학원 IP 등록, 데몬 메모리 실측(개당 ~520MB, 상한 조정), 동시 6명, 상시 구동,
페어링 절차·동의 문구, DNS 레코드·Access 정책(OTP 24h)·검증 7항(specs/110).
**고등 추가**: 데몬·클라이언트 구조, 세션 병렬 시험.

### 11주 — 위임과 검수

| | |
|---|---|
| **만들기 목표** | 프로젝트 중간 결과 + 개선 체크리스트 |
| **개발 역량** | 위임 → 자리 비움 → 검수 사이클, 개선 레버 3종(지시문/설정/스킬화) |
| **사용 기술** | "우리 위키를 아는 AI" 체험 — 쌓인 위키를 AI에게 읽히기 |

**진행**: ① **주중 원격 작업 리뷰** — Slack에서 오간 작업·피드백 팀별 확인, 방향 재설정,
재위임 → ② 자리 비우기 실습 — 그 사이에 **README·문서 구조화**(남이 봐도 읽히게) +
위키 RAG 체험 + 개선 레버 정리 → ③ 재검수 → 12주 발표 준비 확인.
정리된 README·커밋 이력은 수료 후 GitHub로 그대로 이전된다(specs/060) — 포트폴리오의 마지막 조각.
**강사 준비**: 위키 기반 체험 자료.
**고등 추가**: 설정 직접 수정 전후 비교, **TDD 맛보기**(검증 기준을 먼저 쓰고 AI에게
통과시키게 한다 — 프로젝트 한 조각에 적용), 체험을 프로젝트에 바로 연결.

### 12주 — 숫자로 증명한다 ★불가침

| | |
|---|---|
| **만들기 목표** | 1주차 과제 재도전 → 개선률 + 프로젝트 완성 |
| **개발 역량** | 제한 시간 스프린트, 정량 회고 |
| **사용 기술** | 사용량 비교, 커밋·위키 이력 회고 |

**진행**: 2차 스프린트 40분 → 개선률 각자 확인 → 휴식 → 프로젝트 마무리 30분 →
**프로젝트 발표 25분** — 팀당 5분, 5주차 슬라이드 스킬로 직접 만든 자료. 무엇을 만들었나 ·
AI에게 뭘 맡겼나 · 뭐가 잘 안 됐나. **순위·시상·투표는 없다** — 비교 대상은 끝까지 1주차의
자기 자신뿐 → 위임 회고 서면 한 장 → 커밋·위키 회고 → 집에서 이어가는 법: GitHub
계정(gmail) → `git push --mirror`로 12주 이력 통째 이전 → 수료.
목표 문장: "같은 결과물, 절반의 사용량."
**강사 준비**: 1주차 기록 정리, 스프린트 과제 확정, 수료증.
**고등 추가**: 프로젝트 요약 1장 (진로 서류 참고용).
