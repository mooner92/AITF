# AI 특강 상세 운영 계획

> **내부 검토용** — 강사·원장 컨펌을 위한 상세 문서입니다.
> 학부모·학생 배포용 요약본은 [`class-plan.md`](class-plan.md)입니다.
> 10주차 진행에는 서프라이즈 구성이 있어, 학생에게는 이 문서를 배포하지 않습니다.

---

## 1. 수업 정체성 — 코딩학원 수업으로서

### 이 수업이 실제로 가르치는 것

겉으로 보이는 결과물은 그림·발표자료·이야기책·영상이지만, **진짜 커리큘럼은
"터미널 환경에서 AI 에이전트를 부리는 개발 워크플로"입니다.** 결과물은 그 역량을
익히게 만드는 재료입니다.

2026년 현재 개발 현장의 표준 작업 방식이 바로 이것입니다 — 터미널에서 AI 에이전트에게
일을 시키고, 결과를 검증하고, 버전 관리로 기록하는 흐름. 이 수업을 마친 학생은
**실무 개발자가 매일 쓰는 것과 동일한 환경**을 12주간 몸에 익힌 상태가 됩니다.

### 일반 AI 교양 수업과의 차별점

| | 일반 AI 교양 수업 | 이 수업 |
|---|---|---|
| 환경 | 웹 챗봇 (ChatGPT 웹사이트 등) | **리눅스 서버 + 터미널 + CLI 에이전트** |
| AI의 역할 | 질문에 답해주는 상대 | **파일을 만들고 코드를 짜는 작업 도구** |
| 결과물 | 대화 기록 | 웹페이지·슬라이드·영상 등 **실제 파일**, git 이력 |
| 배우는 것 | 프롬프트 요령 | 프롬프트 + **파일 시스템, 버전 관리, 프로젝트 구조, 도구 설정** |
| 끝나면 남는 것 | 경험 | **포트폴리오 웹페이지 + 12주 커밋 이력 + 개발 환경 적응력** |

### 매주 두 겹으로 진행됩니다

모든 주차는 **[만들기 목표]와 [개발 역량 목표]를 동시에** 가집니다.
학생에게는 만들기 목표만 보이고, 개발 역량은 그 과정에서 자연스럽게 쌓이도록 설계했습니다.

예: 5주차 "발표 슬라이드 만들기"를 하는 동안 학생은 실제로는
HTML 문서 구조 읽기 · 마크다운 문법 · 프로젝트 폴더 정리 · 파일 미리보기 검증을 배웁니다.

## 2. 수업 환경 (원장님 참고용)

| 구성 요소 | 설명 |
|---|---|
| **접속** | 학원 노트북 브라우저 → 전용 주소 → 바로 터미널. 설치·가입 없음 |
| **서버** | 학원 전용 리눅스 서버. 학생별 독립 계정 (서로 파일 접근 불가, 관리 권한 없음) |
| **AI 에이전트** | 터미널에서 동작하는 CLI 에이전트. 대화로 파일 생성·수정·이미지 생성까지 수행 |
| **작품 확인** | 학생별 작품관 웹페이지 — 만든 것을 브라우저로 즉시 확인, 링크 공유 가능 |
| **버전 관리** | 학원 내부 git 서버. 매주 작업 이력이 기록됨 |
| **사용량 관리** | 강사 대시보드에서 학생별 AI 사용량·서버 자원·진도 실시간 확인 |
| **비용 통제** | 학생 계정별 AI 사용 상한 설정. 이미지 생성은 주당 장수 제한 |
| **백업** | 매 수업 후 전원 스냅샷. 실수로 지워도 복구 가능 |

**안전**: 학생 계정은 3중으로 격리됩니다 — ① 리눅스 계정 격리 ② 에이전트가 작업 폴더
밖에 쓰기 불가 ③ 위험 명령은 학생 승인 후 실행. 한 학생의 실수·폭주가 다른 학생이나
서버에 영향을 줄 수 없는 구조입니다.

## 3. 개발 역량 로드맵 (12주 누적)

각 주차에 새로 등장하는 터미널·개발 역량입니다. 앞 주차 역량은 계속 반복 사용됩니다.

| 주 | 새로 익히는 개발 역량 | 도구·개념 |
|:--:|---|---|
| 1 | 터미널 첫 경험 — 화면 구성, 세션, 기본 탐색 | tmux, `ls` `cd` `cat`, 프롬프트 입력 |
| 2 | 파일과 폴더 구조, 파일→브라우저 연결 이해 | 디렉토리 트리, HTML 파일, 웹페이지가 파일이라는 감각 |
| 3 | 실험과 비교 — 입력을 바꾸면 출력이 바뀐다 | 명령 히스토리(`↑`), 결과 비교, 기록 습관 |
| 4 | 바이너리 파일 다루기 | 이미지 파일·확장자·용량(`du`), 생성 파일 검증 |
| 5 | 문서 마크업 | 마크다운 문법, HTML 구조 읽기(태그·계층), 폴더 정리 |
| 6 | **버전 관리 시작** | `git add / commit / push`, `git status`·`log` 읽기 |
| 7 | 프로그램 실행과 파이프라인 | 명령행 도구 실행(영상 변환), 입력→처리→출력 개념 |
| 8 | 문서화 + **에이전트 관리 도구** | README, 커밋 정리 + 멀티 에이전트 지휘 도구(데몬·클라이언트) 개념 |
| 9 | 프로젝트 설계 | 작업 분해 — "AI에게 맡길 일 vs 사람이 할 일" |
| 10 | **설정 파일 읽기 + 위임 개시** | 설정(TOML)·규칙(MD) 문법 + 비동기 작업 위임 |
| 11 | **위임·검수 + 설정 수정** | 걸어둔 작업 검수, 설정 변경→효과 확인 (고등: 직접, 중등: 데모) |
| 12 | 종합 — 스프린트 + 팀 발표 | 효율 측정, 위임 회고, 커밋 이력 회고 |

**6주차 git 도입이 이 수업의 "코딩학원다움"을 가르는 지점입니다.** 이후 모든 주차의
마무리가 커밋이 되고, 12주차에 학생은 자기 커밋 이력을 보며 "이게 실무에서 쓰는
방식"임을 확인합니다.

### 1주 — AI를 부려본다

| | |
|---|---|
| **만들기 목표** | AI가 만든 나만의 터미널 명함 (아스키아트 + 한 줄 소개) |
| **개발 역량** | 터미널 첫 경험: tmux 화면, 키보드 조작, 기본 명령 3개 |
| **사용 기술** | 브라우저 터미널, CLI 에이전트 첫 대화 |

**진행**: 완성 예시 시연("12주 뒤 여러분의 작품관") → 접속 5단계 실습 → tmux 키보드
기초(치트시트 배포: 스크롤·중단·창) → 용어 3개만(프롬프트/에이전트/토큰) → 첫 프롬프트로
명함 만들기 → 사용량 그래프 첫 공개("여러분이 쓴 만큼 여기 찍힙니다") → 수준 확인 10분(짝 편성용).

**강사 준비**: 완성 예시 명함·작품관 데모, tmux 치트시트 인쇄, 계정 카드 배부.
**측정 기준점**: 이 주의 과제 기록이 12주차 비교의 1차 기준이 됩니다 (기록 보존).

### 2주 — 내 작품관 개관

| | |
|---|---|
| **만들기 목표** | 내 소개 웹페이지 — 브라우저로 실제 열어본다 (첫 시각적 성취) |
| **개발 역량** | 폴더 구조, "웹페이지 = 파일" 이해, 수정 요청 반복 루프 |
| **사용 기술** | 에이전트의 파일 생성·수정, 작품관 주소로 확인 |

**진행**: "채팅 AI와 뭐가 다른가" — 에이전트가 파일을 직접 만드는 것을 시연 →
각자 소개 페이지 생성 → **브라우저 새로고침으로 즉시 확인** → 수정 요청 반복
(색·글꼴·내용) → "고쳐줘"보다 "○○를 ○○로 바꿔줘"가 잘 먹히는 경험 → 작품관 구조
안내("매주 여기에 전시합니다").

**교육 포인트**: 수정 요청 루프가 이 수업 전체의 기본 동작입니다. 여기서
"구체적으로 시키면 구체적으로 나온다"를 몸에 새깁니다.
**강사 준비**: 작품관 템플릿(전 학생 동일 뼈대), 페이지 서빙 경로 사전 구축.

---

### 3주 — 지시문의 기술

| | |
|---|---|
| **만들기 목표** | 같은 요청·다른 지시문 실험 리포트 (작품관 게시) |
| **개발 역량** | 통제 변인 실험, 히스토리 활용, 결과 기록 습관 |
| **사용 기술** | 프롬프트 구성 요소(역할·맥락·형식·예시), 결과 비교 |

**진행**: 같은 목표("내 소개 페이지에 취미 섹션 추가")를 5가지 지시문으로 →
결과를 나란히 비교 → 무엇이 결과를 갈랐나 토론 → 좋은 지시문의 4요소 정리 →
실험 리포트를 페이지로 작성.
**고등 추가**: 사용량 그래프에서 입력/출력 구분 읽기 — "긴 지시문은 비싸다,
그러나 재시도 3번보다 싸다"는 트레이드오프.

**교육 포인트**: 4주부터의 스킬 위크가 전부 이 지시문 역량 위에서 돌아갑니다.
여기서 잡히지 않으면 스킬 위크가 "버튼 누르기"가 됩니다.

### 4주 — 스킬 위크 ① 그림

| | |
|---|---|
| **만들기 목표** | AI로 만든 내 포스터 또는 캐릭터 (작품관 전시) |
| **개발 역량** | 이미지 파일 다루기 (확장자·용량·저장 위치), 생성물 검증 |
| **사용 기술** | **이미지 생성 기능** (에이전트 내장) — 주당 20장 제한 |

**진행**: "스킬" 개념 첫 등장 — "매주 새 장비를 하나씩 드립니다" → 이미지 생성 시연 →
장수 제한 안내("20장 안에서 원하는 그림을 뽑는 게임입니다") → 각자 제작: 프롬프트 구체화
→ 생성 → 평가 → 수정 반복 → 베스트컷을 작품관에 전시 + 어떤 지시문으로 뽑았는지 함께 기록.

**교육 포인트**: 장수 제한은 비용 통제이자 핵심 교육 장치입니다 — 3주차의 지시문 역량이
좋을수록 적은 장수로 원하는 그림이 나옵니다. **"AI는 공짜가 아니다 + 잘 시키면 싸다"**를
숫자로 처음 체감하는 주.
**강사 준비**: 장당 비용 실측 → 상한 확정, 프롬프트 예시 카드(스타일·구도·조명 어휘).

---

### 5주 — 스킬 위크 ② 발표자료 ★실용 정점

| | |
|---|---|
| **만들기 목표** | 5~7장 발표 슬라이드 — **실제 학교 발표에 쓸 수 있는 수준** |
| **개발 역량** | 마크다운 문법, HTML 문서 구조 읽기, 내용→구조→디자인 순서 |
| **사용 기술** | **슬라이드 생성 스킬** (강사 제작·서버 설치) |

**진행**: 좋은 슬라이드 vs 나쁜 슬라이드 3분 → 주제 선정(수행평가 주제 환영, 없으면
제공 목록: 환경·역사 인물·과학 원리 등) → 개요를 마크다운으로 먼저(내용 설계) →
스킬로 슬라이드 생성 → 브라우저에서 넘겨보며 다듬기 → 작품관 전시.
**고등 추가**: 실제 수행평가 주제 강력 권장 + 발표 대본 생성까지. 출처 표기 포함.

**교육 포인트**: "내용을 먼저 설계하고 형식은 도구에 맡긴다" — 실무 문서 작업의 핵심 순서.
**"학원에서 만든 걸 학교에서 그대로 썼다"가 나오면 이 과정 최고의 성과이자 홍보입니다.**
**강사 준비**: 슬라이드 스킬 제작·테스트(HTML 기반, 외부 서비스 불필요), 주제 목록 10개.

---

### 6주 — 스킬 위크 ③ 이야기책 + git 시작

| | |
|---|---|
| **만들기 목표** | 글+그림 이야기책 (웹에서 넘겨보는 형태, 작품관 전시) |
| **개발 역량** | **git 3동작 (add/commit/push)**, `git status`·`log` 읽기 |
| **사용 기술** | **스토리북 스킬** (강사 제작) + 이미지 생성 (4주 역량 재사용) |

**진행**: 줄거리 5장면 설계 → 장면별 삽화 생성(4주차 프롬프트 역량 재사용 — 스타일
통일이 이번 주 도전) → 스킬로 책 형태 조립 → **git 도입**: "작품이 쌓이니 이제
기록합니다" — 사물함(저장소)·세이브(commit)·업로드(push) 비유, 3줄 실습 →
이야기책이 첫 공식 커밋이 됨.
**고등 추가**: 자작 스킬 과제 시작 — "네가 반복하는 작업을 도구로 만들어라" (8주까지).

**교육 포인트**: git을 "배워야 할 것"이 아니라 "내 작품을 지키는 도구"로 도입합니다.
이후 매주 마무리 = 커밋. 계정·저장소·연결은 전부 사전 세팅되어 학생은 3줄만 칩니다.
**강사 준비**: 스토리북 스킬 제작·테스트, git 비유 슬라이드.

---

### 7주 — 스킬 위크 ④ 움직이는 작품

| | |
|---|---|
| **만들기 목표** | 내 작품이 움직이는 짧은 영상 (30초 내외, 작품관 전시) |

## 8. 확정이 필요한 사항 (원장님 협의)

   상이하므로 "AI 활용 명시" 지도 방침 포함 권장)
