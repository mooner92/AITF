# 금요일 현장 리허설 — 순차 테스트 파이프라인

> 개강 이틀 전, 학원 노트북·네트워크에서 **1주차부터 이어서 여러 주차를 한 번에** 시험합니다.
> 실제 수업은 한 주씩 간격을 두고 진행되지만, 이 리허설은 대기 시간이 없으므로
> 한 시간 안에 2~3주 진도까지 계속 밀고 나갈 수 있습니다. 목적은 두 가지입니다 —
> ① 지금 진행 중인 수업 진도(1~3주차)가 실제로 매끄럽게 도는지 확인하는 것,
> ② 시험에 쓴 계정을 원래 상태로 되돌려 다음 리허설이나 실제 개강에 재사용하는 것.

**관련 문서**: [`specs/130-prelaunch-plan.md`](../specs/130-prelaunch-plan.md#개강-이틀-전--학원-현장-리허설-금요일) ·
[`curriculum/detailed-plan.md`](../curriculum/detailed-plan.md) (체크리스트 원문 출처)

---

## 이 문서의 쓰임

- `scripts/test-pipeline.sh` 가 아래 체크리스트를 요약해 순서대로 띄우고, 항목마다 강사가
  확인 후 Enter(통과) 또는 `x`+한 줄 메모(문제 기록)로 응답하면 로그 파일에 시각과 함께 남깁니다.
- 이 문서가 **정본**이고 스크립트의 `WEEK_*` 배열은 그 요약본입니다. 커리큘럼이 바뀌면
  이 문서를 먼저 고치고, 스크립트 배열을 맞춰 갱신합니다.
- 항목마다 **solo**(강사 혼자 학생인 척 시험 가능) / **classroom**(진짜 학급이 있어야 의미
  있는 항목 — 짝 활동, 반응 관찰, 투표 등)을 표시합니다. 리허설에서 classroom 항목은
  스크립트가 자동으로 건너뛰지만, 이 문서에는 "실제 수업에서 확인할 것"으로 남겨둡니다.

## 실행 순서 (당일)

```bash
# 1. 시험 계정 준비 (처음이거나, 이전 리허설 뒤 리셋이 필요하면)
sudo ./scripts/reset-test-account.sh test1

# 2. 1~3주차를 이어서 시험 (주차 사이 자동 리셋 없음 — 실제 학생처럼 상태 유지)
sudo -u test1 ./scripts/test-pipeline.sh test1 1 3
# (원장 자리에서 그대로 보게 하려면 tmux 창 하나를 프로젝터에 띄워둔다)

# 3. 문제가 발견되면 Claude Code를 학원 노트북에서 띄워 서버 로그와 대조하며 즉시 진단
#    (아래 "문제 발견 시 진단 절차" 참고)

# 4. 리허설이 끝나면 계정을 처음 상태로 되돌려 다음 시험이나 실제 개강에 대비
sudo ./scripts/reset-test-account.sh test1
```

**한 시간 예상 배분**: 계정 준비 5분 + 1주차 25분 + 2주차 15분 + 3주차 15분 = 60분.
시간이 남으면 4주차 이후는 아직 이 문서에 없으므로, 우선 1~3주차를 여러 번 반복하며
재현성(같은 문제가 다시 나오는지)을 확인하는 데 씁니다.

## 1주차 — 터미널과 첫 대화

| # | 항목 | 구분 | 확인 기준 |
|---|---|---|---|
| 1 | 계정 카드로 브라우저 터미널 접속 (5단계) | solo | 실제 소요 시간 측정 — 25분 가정과 비교 |
| 2 | tmux 3키 (스크롤 / 세션 중단 / 재입력) | solo | 세 동작 모두 실제로 동작 |
| 3 | Codex CLI 첫 대화, 세션 유지 확인 | solo | 터미널을 닫았다 다시 열어도 세션이 살아있음 |
| 4 | 프로필 카드 — 웹 검색으로 정보 조사 → 터미널 카드 생성 | solo | 실제 웹 검색 결과가 카드에 반영됨 |
| 5 | 할루시네이션 시연 — 검색 없이 인물 질문 | solo | 근거 없는 답이 나오는 현상 재현 |
| 6 | 사용량 그래프 확인 | solo | 이번 시험의 사용량이 12주차 비교 기준점으로 기록됨 |

어느 단계에서 막혔는지(계정 카드 인식 / 브라우저 호환 / 서버 응답)를 정확히 기록합니다.

## 문제 발견 시 진단 절차

1. `test-pipeline.sh`가 남긴 로그에서 `⚠` 표시된 항목을 확인 (`grep '⚠' <로그파일>`)
2. 그 시점 전후의 서버 로그를 Claude Code로 조회 — 학원 노트북에서 Claude Code를 직접 띄워
   `journalctl`, nginx 로그, systemd 서비스 상태 등을 그 자리에서 읽고 원인을 좁힌다
3. 원인이 계정 설정(하네스·포트·git 배선)이면 `scripts/reset-test-account.sh`로 다시 리셋 후
   재현 시험 — 우연이 아니라 재현되는 문제인지 확인
4. 원인이 방화벽·포트라면 **그 자리에서 고치지 않는다** — "방화벽/포트 변경은 반드시
   운영자 확인 후"라는 기존 원칙을 리허설 중에도 그대로 지킨다. 증상과 원인 후보만 기록해 둔다
5. 고친 내용은 해당 `specs/NNN-*.md`의 결정 기록에 남기고 커밋

2. 각 항목에 solo/classroom을 매긴다 — 판단 기준은 "강사 혼자 학생 역할을 해도 검증되는가"
3. `scripts/test-pipeline.sh`의 `WEEK_*` 배열에 같은 내용을 `"설명|solo"` 또는
   `"설명|classroom"` 형식으로 추가한다 (`WEEK_4=(...)` 새 배열, 스크립트의 `week_array_name`
   함수가 자동으로 찾는다 — 스크립트 본체 수정 불필요)
4. 이 문서 하단에 새 절을 추가하고 git commit

## 결정 기록

- 2026-08-24 · 주차 사이 **자동 리셋 없음**으로 설계. 실제 학생은 상태가 주차 간 이어지므로,
  리허설도 이어지는 상태에서 문제를 잡아야 실전과 같은 신호를 얻는다. 리셋은
  `reset-test-account.sh`로 원할 때 별도 실행.
- 2026-08-24 · classroom 항목은 **삭제하지 않고 표시만 하고 건너뜀**. 리허설에서 검증
  불가능하다고 체크리스트에서 지워버리면 실제 수업 전 확인해야 할 항목이라는 사실 자체가
  사라진다.
- 2026-08-24 · 체크리스트 정본은 이 문서, 스크립트는 요약본. 스크립트만 고치면 다음
  리허설 때 "왜 이 항목이 바뀌었는지" 기록이 안 남으므로 문서 우선 원칙을 유지한다.
