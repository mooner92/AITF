### 1. 첫 위임 실습이 **전원 실패**한다 — 정리할 파일이 없다

**문제**: 덱 실습 2의 워밍업 위임 `"지난주에 올린 파일들을 w01 폴더로 정리해줘"`가
어느 반에서도 성립하지 않는다.

**근거 [확인]** — 13명 전원의 홈·Gitea를 조회:

- Class 2 (6명): Gitea에는 파일이 있으나(`geonbag1015_V1.html` 등) **홈 working copy는 커밋 0개**.
  브라우저 업로드는 Gitea 베어 저장소에만 들어가고 학생 홈에는 닿지 않는다.
  `noonsongi1000` 기준 `git status` → `No commits yet on main`, 홈에는 템플릿 파일만.

즉 Codex를 켜고 "지난주 파일 정리해줘"라고 하면 **정리할 대상이 화면에 없다.**
덱의 대비책("파일이 없는 학생은 빈 w01 폴더만 만들어줘")은 Class 1용으로 쓴 것인데,
실제로는 Class 2까지 전원이 그 경로로 빠진다 — 실습의 의미(파일 이동을 말로 시킨다)가 사라진다.

**조치** (택1):
- (a) **Class 2에게 `git pull`을 먼저 시킨다** — Gitea의 자기 파일을 홈으로 내려받는 장면이
  추가되고, 그 다음 정리 위임이 원래 의도대로 작동한다.
  [확인] `sudo -u noonsongi1000 git fetch origin main` 성공 — 저장된 자격증명으로 인증 통과,
  원격에 `cho_jeogbeam_profile.html` 등 실재 확인. pull도 동일 경로라 동작 [추정].
  다만 학생에게 `git`을 4주차 전에 노출하게 된다 — "지난주 올린 걸 서버로 가져오는 명령"
  정도로 넘기면 커리큘럼 순서와 충돌하지 않는다.
- (b) 위임 문구를 바꾼다 — "지금 폴더를 w01/w02로 정리해줘"처럼 **현재 있는 파일** 기준으로.
  Class 1은 `README.md`·`work/` 등 템플릿 파일이라도 대상이 된다.
- (c) Class 1 Gitea 보충 업로드를 **실습 2보다 앞에** 배치하고(현재도 앞), 업로드 직후
  `git pull`로 내려받게 해 양 반의 상태를 같게 만든다 — (a)의 변형.

**소요**: 덱 2~3장 수정 15분 + 대본 동기화 5분.

## 🟡 이번 주

### 2. 로그 로테이션이 없다 — /var/log가 이미 363MB

**소요**: 10분.

### 3. cron 체인이 실패를 삼킨다

**근거 [확인]** `/etc/cron.d/aitf-wiki`:
```
0 20 * * 0 root /opt/scripts/build-wiki.py >> ... 2>&1 && { publish-notion.py; notify-slack.py; } >> ... 2>&1
```
- `&&` 때문에 **build-wiki가 실패하면 Notion·Slack이 통째로 안 돈다** — 이건 의도된 설계로 보임(정본 먼저).
- 반대로 `{ A; B; }`는 세미콜론이라 **publish-notion이 죽어도 notify-slack은 실행된다** — 이것도 합리적
  (알림은 위키 링크만으로도 성립).
- 다만 **실패해도 아무도 모른다**. 로그에만 남고 알림이 없다. 일요일 밤 파이프라인이 조용히
  깨져 있으면 월요일에야 발견.

**조치**: 선택 — cron 실패 시 Slack 강사 DM 한 줄. 또는 관제탑에 이미 "자동화 마지막 실행 시각"이
표시되니(오늘 wiki_built 버그 고침) 그걸로 갈음.
**소요**: 알림 추가 시 20분.

### 4. 기존 서비스 하나가 인터넷에 직접 노출 (우리 것 아님)

**근거 [확인]**: 외부에서 실제 접속 테스트 —
- `⟪서버_IP⟫:80` → 차단(정상, Cloudflare 터널만 통과)
- `:13000` → 차단(정상)
- **`:3001` → 열림.** 정체: `opc` 사용자의 `trading-bot/src/dashboard/server.js` (BitRocket Dashboard),
  응답 HTML 확인됨.

**우리 수업과 무관한 기존 서비스**지만, 같은 서버라 침해 시 학생 계정·키까지 영향권이다.
`iptables INPUT`은 policy ACCEPT에 룰 0개 — 즉 OCI 보안목록에서 3001이 허용돼 있다는 뜻 [추정].

**조치**: 강사 판단 — 대시보드를 계속 공개할 필요가 있는지, 없으면 OCI 보안목록에서 3001 닫기.
**방화벽 변경이라 사전 승인 필요** (repo 원칙).
