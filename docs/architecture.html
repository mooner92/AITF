AITF · 서버 구조 설명

지금까지 만든 것의 해부도

코딩학원 AI 특강 서버가 어떤 층으로 쌓여 있고, 각 층이 왜 거기 있는지 정리했습니다. 바깥에서 들어오는 길, 학생 계정 안에서 일어나는 일, 그리고 지금 어디까지 됐는지 순서입니다.

한 문장 요약

기존에 돌던 서버 위에, 수업용 층을 겹쳐 올렸습니다

이 서버는 원래 다른 서비스가 돌고 있던 공용 서버입니다. 그래서 모든 설계가 기존 서비스를 건드리지 않으면서 수업용 환경을 옆에 세우는 방향으로 잡혀 있습니다. 학생은 리눅스 계정으로 들어오고, 브라우저 하나로 접속하며, 서로의 파일도 제 설정도 볼 수 없습니다.

복잡해 보이는 이유는 층이 다섯 개이기 때문입니다. 하나씩 보면 각각은 단순합니다.

첫 번째 그림

바깥에서 서비스까지 들어오는 길

학원 노트북에서 주소를 치면 요청이 이 경로를 지납니다. 여기서 헷갈리기 쉬운 게 nginx가 왜 중간에 끼어 있는가인데, 그 이유가 그림에 나옵니다.

지금 상태

서버 포트는 바깥에 하나도 열려 있지 않습니다. 모든 서비스가 127.0.0.1에만 묶여 있고, Cloudflare 터널이 유일한 입구입니다. 다만 아직 Access 정책이 없어서 주소를 아는 사람은 로그인 화면까지는 도달합니다 — 이게 지금 가장 먼저 처리할 일입니다.

두 번째 그림

학생이 로그인한 뒤 벌어지는 일

학생 계정 안쪽 구조입니다. 여기가 하네스와 모델 라우팅이 사는 곳이고, 10주차 리빌의 재료가 되는 부분입니다.

다섯 개의 층

각 층이 무엇이고 왜 거기 있는지

1 · 접속 층 Cloudflare 터널 + nginx

학원 노트북 브라우저 하나로 들어옵니다. 서버 포트는 바깥에 열지 않고, 터널이 유일한 입구입니다. 한 서브도메인 아래 경로로 서비스를 나눕니다 — 다른 서브도메인은 기존 서비스들이 쓰고 있어서입니다.

왜 nginx가 필요했나: 터널은 경로를 다시 쓰지 못합니다. Gitea는 접두사를 프록시가 떼어주길 기대하고, OpenObserve는 스스로 처리합니다. 이 차이를 흡수할 층이 하나 필요했습니다.

2 · 격리 층 리눅스 계정 + systemd + 샌드박스

학생마다 리눅스 계정 하나. 홈은 700이라 서로의 파일을 못 봅니다. sudo는 없습니다. 계정별 메모리 상한(1536M)과 프로세스 수 상한이 걸려 있어서, 한 명이 폭주해도 다른 학생과 기존 서비스가 멀쩡합니다.

3중 방어: 리눅스 계정 격리 → CLI 샌드박스(작업 폴더 밖 쓰기 차단) → 승인 정책(위험한 명령은 학생에게 확인). 마지막 것은 안전장치이자 "AI가 뭘 하려는지 보고 승인하는" 습관을 기르는 교육 장치입니다.

3 · 하네스 층 /opt/harness · root 소유

학생이 쓰는 AI의 행동을 감싸는 부분입니다. 세 가지가 들어 있습니다: 모델 라우팅(어떤 일에 어떤 모델을 쓸지), 프로젝트 맥락(이번 기수 스택과 자주 나는 에러의 해법), 교육 원칙(고치기 전에 왜 틀렸는지 쉬운 한국어로 먼저 설명할 것).

세 번째가 이 수업의 존재 이유입니다. AI가 조용히 고쳐주면 학생은 아무것도 배우지 못합니다. 파일은 root 소유라 학생이 수정할 수 없고, 전역 gitignore가 저장소 유출도 막습니다.

4 · 관측 층 수집 스크립트 + OpenObserve

1분마다(수업 시간대) 학생별로 세 가지를 모읍니다: 토큰 사용량, 리소스(메모리·CPU·프로세스 수), 진도(커밋 수·마지막 활동 시각). 수업 중에 누가 막혀 있는지, 누가 메모리 상한에 근접했는지 한 화면에서 보입니다.

학생은 이 화면을 볼 수 없습니다. 학생도 서버의 로컬 계정이라 루프백 주소로 접근이 가능하기 때문에, 도구 자체의 로그인을 통과해야만 데이터가 보이도록 했습니다.

5 · 안전망 층 /opt/scripts · /srv/snapshots

수업 후 반 단위 스냅샷(이전 스냅샷과 중복 제거해서 12주 쌓아도 용량이 거의 안 늘어남), 사고 시 학생 단위 복구, 종강 후 아카이브. 스냅샷마다 진도 요약표가 자동 생성돼서 뒤처진 학생을 훑어볼 수 있습니다.

복구 스크립트가 새 사고를 만들 뻔했습니다. 초기 버전이 홈을 통째로 덮어써서 git 자격증명까지 지웠습니다 — 복구된 학생은 그날부터 push를 못 하게 됩니다. 실측으로 발견해서 고쳤고, 지금은 파일 삭제 → 복구 → push까지 왕복 검증을 통과합니다.

규칙만으로는 언젠가 실수가 나므로 커밋 차단 훅을 걸어 뒀습니다. API 키 패턴, 공인 IP, 식별자 형식, 금지 파일명을 스캔해서 발견되면 커밋을 거부합니다. 실제로 한 번 잡았습니다 — 플러그인이 저장소 안에 만든 세션 로그가 커밋에 딸려가려던 것을 막았습니다.

지금 막혀 있는 것

서버 쪽 작업 대부분은 끝났고, 남은 것은 대체로 바깥에서 받아와야 하는 것들입니다.

  • Access 정책 — 지금 로그인 화면이 공개 노출 상태라 가장 급합니다. 이게 끝나야 학생 터미널 경로도 켤 수 있습니다.
  • API 키 — 하네스 동작 검증, 모델 라우팅 비율 확인, 실제 CLI 부하 재시험이 전부 여기에 걸려 있습니다.
  • 학원 고정 IP — 학생 접속 방식(자동 통과 vs 개별 인증)이 여기서 갈립니다.
  • 학생 명단 — 계정·저장소 일괄 생성의 입력값입니다.
  • 부트 볼륨 백업 — 최후 복구 지점.
단계별 상세 스펙과 결정 기록은 저장소의 specs/에, 실제 값이 들어간 운영 노트는 서버의 ~/class-setup/에 있습니다.
