# Week 00 — 세팅 일지

## 2026-08-16 · 서버 실사 + 계획 수립

수업 서버로 쓸 기존 OCI 인스턴스를 실사하고 세팅 계획을 스펙(specs/)으로 정리했다.

**실사에서 배운 것 (계획이 3번 바뀐 이유):**

1. "인스턴스 리사이즈가 필요하다"고 알고 있었는데, 메타데이터를 조회해 보니 이미 무료 한도 최대 셰이프(4 OCPU/24GB)였다. → 추측 말고 `curl`로 메타데이터를 직접 확인할 것.
2. 루트 디스크가 96% 차 있어서 큰일 난 줄 알았는데, `lsblk`를 보니 부트 볼륨 200G 중 155G가 파티션 밖에 미할당 상태였다. → 콘솔 작업 없이 서버 안에서 확장 가능. "디스크 부족"과 "볼륨 부족"은 다른 문제다.
3. 이 서버는 전용이 아니라 기존 서비스가 함께 도는 공용 서버다. → 두 가지 설계 변경: ① 127.0.0.1 바인딩만으로는 로컬 계정(학생)을 못 막으므로 내부 서비스에 인증 추가 ② 부하 테스트 통과 기준에 "기존 서비스 무영향" 추가.

**오늘 한 것:** 저장소 개설, 공개/비공개 2-존 정책(SECURITY.md) + pre-commit 시크릿 스캔 훅, specs 000~100 작성, 운영 스크립트 공개 버전 작성.

**다음:** 부트 볼륨 백업(운영자) → 디스크 확장 → P1 잔여 → P2 접속 경로.

## 2026-08-16 (2차) · 마감의 정체 확인 + 커리큘럼 확정

- 어제까지 "8/18 마감이 뭐지?"였는데, 검색으로 확인: **Oracle이 6/15부터 Always Free A1 한도를 4 OCPU/24GB → 2 OCPU/12GB로 반감**했고(공지 없이), **8/18부터 초과 인스턴스 자동 종료**를 집행한다. 어제 "축소 불필요"라고 판단했던 것은 오판 — 스펙 010의 결정 기록에 그대로 남겼다. 배운 것: 메타데이터는 현재 상태만 알려주고, 정책 변화는 알려주지 않는다.
- 수업 확정: **일요일 14–16 중등반 / 16–18 고등반**, 12주, 반당 ~6명. 두 반 사이 텀이 0분이라 교대 루틴을 새로 설계했다 (교대 시엔 정리만, 스냅샷은 수업 후로).
- tmux는 마우스 모드 없이 **키보드로 가르치기로** — 치트시트 준비.
- 모니터링을 토큰만이 아니라 **리소스(계정별 메모리·CPU)와 진도(커밋·최근 활동)**까지 한 화면으로 확장.
- 커리큘럼 v6 확정 (설계 전문은 비공개, 개요는 `curriculum/overview.md`).

## 2026-08-16 (3차) · 인프라 실구축 — 서버가 실제로 굴러가기 시작

방침 확정: **셰이프는 현행 유지, 8/18은 "세팅 완료" 목표일.** 오늘 구축분:

- **디스크**: 캐시 정리(+9GB) → `oci-growfs`로 루트 29.5G→**183G** (무중단, 기존 서비스 무영향 확인)
- **P1 완료**: htop(EPEL), `/etc/tmux.conf`(history-limit만 — 키보드 교육 방침), 디렉토리 골격+700 권한
- **AI CLI**: codex·gemini·tokscale를 root 전역(`/usr/bin`)에 설치 — 학생 계정에서 실행 확인
- **운영 스크립트 8종** `/opt/scripts` 배치 (root 700)
- **test01 검증 통과**: sudo 거부 / 타 디렉토리 차단 / tmux 자동 진입 / CLI 실행
- **메모리 상한 실측에서 배운 것 2개**: ① MemoryHigh 스로틀은 폭주 프로세스를 "안 죽고 한없이 느리게" 만들어 학생이 원인을 모른다 → 명확한 OOM-kill(Max만)로 정책 변경 ② MemorySwapMax 없으면 폭주가 swap을 잠식해 서버 전체가 느려진다 → 512M 캡 추가. 500M 캡 테스트에서 712ms 만에 정확히 kill 확인
- **Gitea 1.27.2 가동** (arm64 바이너리, 127.0.0.1:3000, 가입 비활성): 첫 기동이 app.ini에 JWT_SECRET을 못 써서 실패 → 미리 생성해 넣는 방식으로 해결 (읽기 전용 설정 파일 유지)
- **git E2E 통과**: test01이 비밀번호 질문 없이 push 성공, `.env`는 전역 gitignore가 자동 차단
- **관측 가동**: 수집 3종(토큰·cgroup 리소스·진도) + cron(일 13–18시 1분/평시 15분) 배치, 1회 실행으로 파이프라인 확인

**다음**: 모니터링 웹(070) → 템플릿 홈+하네스(055) → Cloudflare 경로(030, 학원 IP·도메인 대기) → 리허설

## 2026-08-16 (4차) · 관측 스택 확정 — OpenObserve 채택

- 모니터링 웹을 자작하는 대신 **OpenObserve**(단일 Rust 엔진) 채택 — 운영자 제안 검토 결과: arm64 공식 이미지, 실측 294MB, **내장 인증**이 "학생 루프백 curl" 문제를 그대로 해결(무인증 API 401 실측), SQL 검색 + 대시보드 빌더 내장이라 UI 개발 공수 제거.
- 수집기(collect-tokens.sh)가 `tokens`/`resources`/`server` 3개 스트림으로 push하도록 확장, 인제스트→SQL 조회 왕복 검증 완료.
- 삽질 기록: ① 루트 비밀번호 정책(특수문자 필수)으로 첫 기동 실패 ② 검색 API의 시간 범위는 마이크로초이고 start_time=0이 무효 — 둘 다 해결.
- 잔여: 대시보드 5종 구성은 터널 연결 후 UI에서 (시작 쿼리는 specs/070에 준비).
