# decks — 발표자료

주차별 수업 슬라이드. 원고(`.md`)를 쓰면 자립 실행 HTML 한 파일로 나옵니다.
인터넷 없이 열리고, USB로 옮겨도 그대로 동작합니다.

시각 규칙은 [`docs/design-spec.md`](../docs/design-spec.md)를 따릅니다. 이 문서는 **만드는 절차**만 다룹니다.

**문체는 해요체입니다** (design-spec 2.5) — 수업 슬라이드는 학생에게 보이는 배포물이므로
토스 공고체 기준을 따릅니다: 제목은 문장형("매주 이런 걸 만들어요"), 한 문장에 정보 하나,
주접·비밀주의 금지. 발표자 노트(`???`)는 강사 메모라 한다체·합니다체 무방합니다.

**말로 할 것은 화면에 쓰지 않습니다** (2026-08-29 추가) — "손을 들어볼까요?" 같은
구어 멘트는 슬라이드가 아니라 `wNN-대본.txt` 에 둡니다. 화면은 정보 전달만,
입은 대본이 맡습니다. 역할 분담: `???` 노트 = 운영 지시(시간·대처), 대본 = 실제로
입에 올릴 문장. 원고를 쓰다 "~볼까요?", "~죠?" 로 끝나는 줄이 생기면 대본으로 옮깁니다.

## 빠른 사용

```bash
# 0. 최초 1회 — 설정 파일과 폰트 준비
cp class-config.example.json class-config.json && vi class-config.json
#    Paperlogy TTF 9종을 ../curriculum/fonts/ 에 풀어둡니다 (저장소에 없음)
pip install "fonttools[woff]" brotli

# 1. 원고를 고친다
vi w01-orientation.md

# 2. 빌드
python3 build-deck.py w01-orientation.md

# 3. 검사
python3 ../scripts/check-design.py w01-orientation.html
```

빌드가 **`⚠ 미설정 치환값`** 을 뱉으면 `class-config.json` 에 아직 안 채운 값이 있다는 뜻입니다.
그대로 두면 슬라이드에 `⟪ACCESS_URL 미설정⟫` 이 그대로 뜹니다 — 발표장에서 빈칸을 마주하지 않도록 일부러 눈에 띄게 만들었습니다.

## 원고 문법

| 쓰기 | 뜻 |
|---|---|
| `---` | 슬라이드 구분 |
| `<!-- class: cover g-none -->` | 그 슬라이드의 class |
| `# ## ###` | 제목 |
| `^ 텍스트` | eyebrow (제목 위 작은 라벨) |
| `^^^` | 이 아래는 fragment — 방향키 한 번에 한 덩어리씩 나타남 |
| `??? 텍스트` | 발표자 노트. 화면에 안 나오고 `S` 키로 봄 |
| `{{ACCESS_URL}}` | `class-config.json` 값으로 치환 |
| `{{STUDENTS_MID:list}}` | 배열을 목록으로 (`:table` 도 가능) |
| 표·목록·코드·인용 | 마크다운 그대로 |
| `![캡션](assets/img/파일)` | 이미지 — 빌드 때 파일 안에 인라인됨 (아래 "이미지" 절) |
| `<` 로 시작하는 줄 | 원본 HTML **블록** — 다음 빈 줄까지 통째로 통과. 여러 줄 태그 가능 |

> ⚠ 원본 HTML 블록 바로 다음 줄에 `##` 제목을 붙이면 제목까지 블록에 삼켜져
> 화면에 `## 제목` 이 글자 그대로 뜹니다. **블록과 마크다운 사이엔 빈 줄**을 둡니다.

### 슬라이드 class

| class | 쓰임 |
|---|---|
| `cover` | 표지·마무리 — 왼쪽 정렬, 큰 제목 |
| `chapter` | 간지 — 가운데 큰 번호 |
| `g-none` | 글로우 끔 |
| `g-green` `g-violet` `g-orange` | 글로우 색 (기본은 파랑) |

## 이미지

학생 대상 슬라이드는 글보다 그림이 먼저입니다. 사진·다이어그램을 넣는 규칙:

### 받은 사진을 그대로 쓸 때

1. 파일을 `assets/img/` 에 넣습니다 (jpg·png·webp·svg)
2. 원고에 `![캡션](assets/img/파일명.jpg)` — 캡션은 비워도 됩니다
3. 빌드하면 **파일 안에 base64 로 인라인**됩니다 — 산출물은 여전히 파일 하나입니다
4. 파일이 없으면 빌드가 주황 점선 **자리표시자**를 넣고 경고를 냅니다.
   사진이 아직 안 온 상태에서도 나머지 장을 검토할 수 있고,
   자리표시자가 화면에 뜨면 어차피 눈에 띕니다 (미설정 치환값과 같은 철학)

나란히 놓을 때는 원본 HTML로:

```html
<div class="media-row">
<figure class="media"><img src="assets/img/before.png" alt=""><figcaption>적용 전</figcaption></figure>
<figure class="media"><img src="assets/img/after.png" alt=""><figcaption>적용 후</figcaption></figure>
</div>
```

### 사진이 테마와 안 맞을 때 — 직접 그립니다

받은 이미지가 밝은 배경·다른 색감이라 순흑 캔버스에서 겉돌면, 사진을 억지로 넣지 말고
**같은 내용을 컴포넌트로 다시 그립니다.** 우선순위:

1. **카드 그리드** (`.grid.c3` + `.card`) — 비교·나열은 대부분 이걸로 끝납니다
2. **흐름** (`.flow`) — 순서·단계
3. **막대** (`.bars`) — 수치 비교
4. **인라인 SVG** — 위 셋으로 안 되는 구조도(다이어그램)만. design-spec 4-4 규칙
   (currentColor, 의미 있는 색 하나, `role="img"`)을 그대로 따릅니다

shadcn/ui 컴포넌트의 **디자인 언어**(카드·배지·차트 팔레트)를 가져오되 라이브러리는
가져오지 않습니다 — design-spec 5-3-2와 같은 원칙입니다. 재사용할 만한 조각이 생기면
`assets/` 에 `.html` 조각으로 두고 원고에 붙여 씁니다.

### 사진 넣을 때 지킬 것

- **학생 얼굴·실명이 보이는 사진은 넣지 않습니다** (SECURITY.md와 같은 원칙 —
  슬라이드는 파일로 돌아다닙니다)
- 스크린샷은 **어두운 테마로 찍은 것**이 우선입니다. 밝은 스크린샷은 테두리가
  좁은 화면에서 번쩍입니다
- 한 장에 사진은 1~2개. 사진이 3개 이상 필요하면 장을 나눕니다
- 원본이 5MB를 넘으면 넣기 전에 줄입니다 — 산출물 전체가 그만큼 커집니다

## 조작 (발표 중)

| 키 | 동작 |
|---|---|
| `→` `↓` `Space` | 다음 — fragment가 남아 있으면 그것부터 |
| `←` `↑` | 이전 |
| `F` | 전체화면 |
| `O` | 전체 슬라이드 목록 |
| `S` | 발표자 노트 창 (별도 창, 본 창을 따라감) |
| `.` | 화면 가리기 |
| `?` | 도움말 |
| 숫자 + `Enter` | 해당 장으로 |
| `Esc` | 닫기 |

클릭·터치 스와이프도 됩니다. 현재 장이 주소에 남으므로 새로고침해도 자리를 지킵니다.
`Ctrl+P` 로 인쇄하면 한 장씩 PDF가 됩니다 (fragment는 모두 펼쳐진 상태로).

## 새 주차 원고 만들기

계획서에서 뼈대를 뽑습니다.

```bash
python3 scaffold.py            # 아직 없는 주차만 생성
python3 scaffold.py --week 5   # 5주차만
python3 scaffold.py --force    # 전부 다시 (직접 쓴 내용이 날아갑니다)
```

`curriculum/detailed-plan.md` 의 주차 절에서 만들기 목표·개발 역량·사용 기술·진행·강사 준비를 읽어
채워 넣고, 나머지는 `TODO` 로 남깁니다. **계획이 바뀌면 다시 돌려 갱신할 수 있습니다** —
이미 있는 파일은 덮어쓰지 않으므로 안전합니다.

## 윤문까지 포함한 전체 파이프라인

원고를 그냥 쓰면 문체가 딱딱해집니다. 슬라이드는 **말로 하는 글**이라 문서보다 더 그렇습니다.
그래서 빌드 전에 윤문을 한 단계 넣습니다.

```
  ① 원고 작성        w05-....md 를 직접 쓴다 (scaffold 뼈대에서 출발)
        ↓
  ② 산문만 추출      python3 prep.py extract w05-....md /tmp/w05.txt
        ↓            노트(???)·치환자({{}})·코드블록은 빠진다 — 윤문 대상이 아니다
  ③ 윤문             /humanize-korean  (강도: 기본, 장르: 블로그)
        ↓            말하는 리듬으로 고친다. 수치·고유명사는 보존된다
  ④ 되돌리기         python3 prep.py apply w05-....md /tmp/w05.out.txt
        ↓
  ⑤ 빌드             python3 build-deck.py w05-....md
        ↓
  ⑥ 검사             python3 ../scripts/check-design.py w05-....html
```

②와 ④가 한 쌍입니다. 윤문기는 평문만 다루므로 원고를 통째로 넘기면 `^^^` 같은 표시까지
고쳐버립니다. `prep.py` 가 산문만 번호 블록으로 뽑아내고 같은 번호 자리에 되꽂습니다
(문서 쪽 [`curriculum/htmltext.py`](../curriculum/htmltext.py) 와 같은 방식).

### 윤문할 때 지정할 것

슬라이드는 문서와 다르게 주문합니다.

- **장르**: `블로그` — 슬라이드는 읽는 글이 아니라 말하는 글입니다. `리포트`로 두면 다시 딱딱해집니다.
- **문체**: 해요체 유지를 명시합니다 (design-spec 2.5). 윤문기가 합니다체로 되돌리면 안 됩니다.
- **강도**: `기본`
- **보존**: 수치, 고유명사, `{{...}}` 치환자, 코드블록, `TODO`
- **한 줄은 한 줄로**: 슬라이드 한 줄이 두 줄로 늘어나면 화면을 넘칩니다. 길이를 유지하라고 명시합니다.

### 검수 기준

빌드 후 반드시 **실제로 넘겨봅니다.** 자동 검사가 잡지 못하는 것:

- 한 슬라이드에 6줄을 넘는 본문 (스펙 5-1 위반)
- fragment 순서가 말하는 순서와 어긋남
- 표가 화면 아래로 잘림
- 노트에 적은 시간 배분이 실제 분량과 안 맞음

## 파일

| 파일 | 역할 |
|---|---|
| `engine.css` · `engine.js` | 슬라이드 엔진. 빌드 때 HTML 안에 인라인됩니다 |
| `build-deck.py` | 원고 → HTML. 폰트 서브셋·치환·조립 |
| `scaffold.py` | 계획서 → 주차 원고 뼈대 |
| `prep.py` | 윤문용 산문 추출·복원 |
| `class-config.example.json` | 설정 서식 — 복사해서 `class-config.json` 으로 |
| `w01-orientation.md` | **완성 예시.** 새 원고를 쓸 때 이걸 보고 씁니다 |
| `w02`~`w12` | 뼈대 상태 (`TODO` 가 남아 있습니다) |

`class-config.json` 과 빌드 산출물 `*.html` 은 커밋하지 않습니다 (`.gitignore`).
원고와 엔진만 저장소에 두고, HTML은 필요할 때 빌드합니다.

## API 키는 여기 없습니다

`class-config.json` 에 AI API 키를 넣지 않습니다. 슬라이드는 **학생에게 투사되는 화면**이고,
빌드 산출물은 파일 하나로 공유됩니다. 키가 들어가면 그대로 새어 나갑니다.

키가 필요한 곳은 서버의 계정 생성 절차 한 곳뿐입니다 — `scripts/create-accounts.sh` 가
학생별 `~/.codex/config.toml` (600 권한, 학생 소유)에 씁니다. 슬라이드에는 계정 ID(`mid01`)까지만 나옵니다.
